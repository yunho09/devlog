## 요약
새로운 프론트엔드 배포 서버 이전을 위해 staging과 production 빌드 환경을 분리했습니다. `xquare-user-application` 프로젝트에 `.env.staging`과 `.env.production` 환경변수 파일을 추가하고, staging 전용 빌드 스크립트인 `build:stag`를 구성했습니다. 이를 통해 빌드 타임에 각 환경에 맞는 프론트엔드 URL, API Base URL, GitHub App 설정값이 번들에 올바르게 반영되도록 조치했습니다.

## 변경 내용
- `applications/xquare-user-application/.env.staging` 파일 신규 추가 (스테이징용 `VITE_FRONTEND_URL`, `VITE_API_BASE_URL`, GitHub App `XQUARE-INFRASTRUCTURE-TEST` 설정)
- `applications/xquare-user-application/.env.production` 파일 신규 추가 (프로덕션용 `VITE_FRONTEND_URL`, `VITE_API_BASE_URL`, GitHub App `XQUARE-INFRASTRUCTURE` 설정)
- `applications/xquare-user-application/package.json`에 `build:stag` 스크립트 추가 (`tsc -b && vite build --mode staging`)

## 의도
새 서버(XQUARE-frontend) 이관 작업에 대응하여 스테이징(staging)과 운영(production) 환경의 프론트엔드/백엔드 주소 및 OAuth 연동 앱 정보를 분리하고, 환경별 번들링을 용이하게 수행하기 위함입니다.
