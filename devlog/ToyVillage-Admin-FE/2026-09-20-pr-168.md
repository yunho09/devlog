# 2026-09-20

## 요약
애플리케이션 전반의 시각적 안정성과 사용자 경험을 개선하기 위해 피그마 디자인을 반영한 공통 로딩 스켈레톤 UI를 대거 도입했습니다. 대시보드와 12개의 목록 화면, 10개의 상세 화면 및 8개의 수정 화면에 실제 콘텐츠 구조를 모방한 스켈레톤 컴포넌트를 적용하였습니다. 또한 스크린 리더 등 보조기기를 위한 접근성 처리를 추가하고, 재조회 시 기존 데이터를 유지하면서 로딩 상태를 부드럽게 전환하는 세부 제어를 반영했습니다.

## 변경 내용
- **공통 스켈레톤 컴포넌트 구축**: 헤더, 탭, 테이블, 페이지네이션, 뒤로가기 링크, 카드, 필드, 첨부칩 등 개별 UI 요소의 스켈레톤을 공통 컴포넌트화하여 `src/shared/ui/`에 구현했습니다.
- **목록·상세·수정 화면 적용**: 대시보드를 비롯해 피드, 공지사항, 예약, 종/개체 관리, 작업 보고서, 업무 일지 등의 목록/상세/수정 페이지에 맞춰 스켈레톤 컴포넌트를 각각 결합 및 적용했습니다.
- **E2E 테스트 및 승인 명세서 추가**: 스켈레톤 노출 동작과 시나리오를 검증할 수 있는 E2E 테스트 코드(`loading-skeleton-detail.spec.ts`, `loading-skeleton-list.spec.ts`) 및 마크다운 기반의 시나리오 승인 문서를 작성했습니다.
- **접근성 및 예외 대응**: 보조기기에서 로딩 상태를 올바르게 인지할 수 있도록 스켈레톤 영역에 접근성 마크업을 제공하고, 조회 실패 시 오류 안내 노출 및 재조회 시 기존 데이터 유지 흐름을 보장합니다.

## 의도
지연 시간이 발생하는 데이터 네트워크 요청 과정에서 사용자에게 빈 화면 대신 실제 렌더링될 구조와 유사한 스켈레톤 UI를 즉각적으로 보여주기 위함입니다. 이를 통해 서비스가 원활하게 작동하고 있다는 심리적 안정감을 제공하며, 로딩 중에도 주요 링크 이동 및 탭 전환 등이 차단되지 않도록 하여 체감 사용성을 대폭 끌어올렸습니다.

## 트러블 슈팅
- **스켈레톤의 반응형 레이아웃 및 행/주 수 불일치** → 기기 너비에 맞춰 유동적으로 레이아웃이 변화하도록 반응형 스타일을 수정하고, 테이블의 모킹 행 수와 달력 주 수를 보정하여 부자연스러운 화면 흔들림을 해결했습니다 (`dc17297`).
- **상세 표 화면에서 가로 스크롤 누락** → 데이터가 많은 상세 정보 테이블을 보여줄 때 스켈레톤 상태에서 가로 스크롤이 동작하지 않는 문제가 발생하여, 가로 스크롤 래퍼를 보완 적용했습니다 (`e818643`).
- **운영시간 수정 화면의 로딩 중복 및 오작동** → 운영시간 화면을 조회할 때 상태 값(`status`)이 중복 처리되는 지점을 식별하여 중복을 제거함으로써 불안정한 렌더링을 차단했습니다 (`c0dfea2`).
- **E2E 테스트 중 재조회 스켈레톤 시나리오 실패** → 재조회 흐름 검증 시 테스트가 특정 상태를 올바르게 추적하지 못하던 문제를 해결하기 위해, 검증 대상을 업무관리 상태 탭을 기준으로 하도록 시나리오를 수정하여 정상 통과시켰습니다 (`ed5c792`).
