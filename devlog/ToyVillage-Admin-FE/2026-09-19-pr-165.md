## 요약
공지사항 수정 시 첨부파일(`files`) 목록을 함께 전송하고 관리할 수 있도록 API 계약 및 관련 기능을 개선했습니다. 새 첨부파일 업로드 실패 시 수정 요청이 전송되지 않도록 방어 로직을 추가하여 입력 데이터를 보존하고, 정상적인 변경 사항을 검증할 수 있도록 E2E 테스트를 작성했습니다.

## 변경 내용
- 공지사항 수정 API Contract 문서에 첨부 `files` 속성을 추가하고 상세 구현 계획과 테스트 시나리오를 업데이트했습니다.
- 공지사항 엔티티 타입 정의(`types.ts`)에 파일 관련 필드를 반영했습니다.
- `NoticeForm.tsx` UI 컴포넌트 내에서 공지사항 수정 시 첨부파일 변경 사항을 `files` 목록으로 구성해 서버에 전송하도록 수정했습니다.
- 새 첨부파일 업로드가 실패하는 경우 공지사항 수정 API 요청 자체를 중단하고 기존에 작성 중이던 입력 내용을 화면에 유지하도록 안전장치를 추가했습니다.
- 존재하지 않는 첨부파일 키를 사용할 경우 파일을 찾을 수 없다는 에러 표시를 지원합니다.
- 첨부파일 수정 동작을 검증하기 위한 E2E 테스트 케이스를 새로 추가했습니다.

## 의도
공지사항 수정 과정에서 첨부파일의 유연한 추가 및 삭제 상태를 서버와 정밀하게 동기화하기 위함입니다. 또한, 파일 업로드 도중 발생하는 네트워크 이슈나 에러 상황에서 전체 폼 수정 요청이 정상 처리된 것처럼 잘못 반영되거나 기존에 작성된 폼 데이터가 증발하는 현상을 차단하여 사용자 경험과 시스템 데이터의 정합성을 보장하고자 했습니다.

## 트러블 슈팅
- 문제: 새 첨부파일 업로드가 도중에 실패하면 잘못된 파일 상태로 수정 요청이 가거나, 이미 입력해 둔 폼 정보가 유실될 위험이 있음 → 해결: 업로드 프로세스 결과가 유효하지 않을 때 수정 API 요청을 원천 차단하고 입력 폼을 그대로 유지하도록 비즈니스 흐름을 제어함.
- 문제: 없는 첨부파일 키를 참조하여 발생할 수 있는 잠재적 런타임 오류 → 해결: 잘못된 키 참조 시 "파일을 찾을 수 없다"는 에러 메시지와 예외 처리를 명확하게 구현하여 식별하기 쉽도록 처리함.
