## 요약
본 PR은 ToyVillage 관리자 프론트엔드의 업무관리 기능(목록, 상세, 생성, 수정, 삭제)의 화면 퍼블리싱과 5개의 백엔드 API 연동을 완료한 작업입니다. Figma 디자인 규격에 맞춰 UI 컴포넌트를 정교화하였으며, 다중 담당자 지정을 위한 팀 트리 조회 API 및 트리형 선택 컴포넌트 등의 신규 비즈니스 로직을 구축하였습니다. 기존의 임시 Mock 데이터 의존성을 완전히 제거하고, 실제 API 스펙에 맞춘 계약 테스트(Contract Test) 및 시나리오 검증 체계를 갖추었습니다.

## 변경 내용
- **업무지시 CRUD API 연동 및 Mock 제거**: 업무지시 조회(목록/상세), 생성, 수정, 삭제 API를 실제 연동 코드로 교체하고 더미 데이터를 삭제하였습니다.
- **업무관리 UI 퍼블리싱 고도화**: 업무 목록, 상세 조회(읽기 전용), 생성 및 수정 폼을 Figma(yot 기준) 디자인 가이드라인에 부합하도록 레이아웃과 외형을 개편하였습니다.
- **다중 팀원 담당자 지정 기능**: 업무 담당자 모델을 단일 선택에서 팀 다중 선택(`assigneeIds`) 체계로 전환하고, 계층형 조직도를 다룰 수 있는 `TaskAssigneeTree` 컴포넌트와 '팀 트리 조회 API'를 신설하였습니다.
- **공통 컴포넌트 개선**: `DataTable`에 테이블 스타일 커스텀을 위한 `appearance` 속성을 도입하고 페이지네이션 규격을 다듬었으며, `AttachmentField`가 파일 키를 바인딩하여 업로드 흐름을 처리하도록 확장했습니다.
- **테스트 및 검증 사양 보강**: 신규 API들에 대응하는 계약 검증용 시나리오 문서를 작성하고, 테스트가 고유의 가상 환경에서 안정적으로 동작하도록 API mock 헬퍼를 추가 정의하였습니다.

## 의도
수동으로 관리되던 임시 업무 정보 노출 환경에서 벗어나, 백엔드 서비스와 실제로 통신하는 완성형 업무 지시 기능 시스템을 정립하기 위함입니다. 디자인 가이드를 적극 수용해 기획 의도에 맞는 일관된 UI 사용성을 보장하고, 다중 담당자 배정과 같은 복잡한 비즈니스 요구사항을 처리하기 위해 데이터 모델을 재설계하고 연동 신뢰도를 확보하였습니다.

## 트러블 슈팅
- **표 컨테이너 밖 영역의 컴포넌트 숨김 현상 → 컨테이너 overflow/z-index 조정**: 테이블 내 액션 버튼(케밥 메뉴 등)을 누를 때, 상위 `DataTable` 컨테이너 바깥으로 드롭다운 포털이나 팝오버가 잘려 나가는 버그를 테이블 레이아웃 환경 설정을 다듬어 해결했습니다 (`b70633f`).
- **조직 트리 갱신 시 누락된 기존 담당자 소실 문제 → 선택 상태 보존 장치 구현**: 새로 호출된 팀 트리 정보에 현재 지정된 특정 담당자가 더 이상 포함되어 있지 않더라도, 화면에서 해당 정보가 유실되지 않도록 검증 예외 처리를 주입해 담당자 데이터를 온전히 보존하였습니다 (`94ac4e5`).
- **클라이언트 미정의 상태 코드 수신 시 화면 크래시 문제 → 예외 복구 흐름 구축**: 백엔드가 정의되지 않은 새로운 유형의 업무 보고 상태값을 응답하더라도 UI가 전체 중단(Crash)되지 않도록, 알 수 없는 상태에도 폴백(Fallback)을 적용하여 상세 화면 구조를 정상 유지하도록 보완했습니다 (`3aa27a2`).
- **테스트 격리 실패(배럴 임포트 부작용) → 타겟 직접 임포트 전환**: 특정 테스트 스펙 파일이 상위 경로의 배럴 파일(Barrel Import)을 참조하면서 무관한 `axios` 설정까지 끌고 들어오는 간섭 현상을 발견해, 해당 참조 경로를 개별 모듈 직접 임포트로 경로 우회하여 격리성을 유지했습니다 (`d2567cd`).
