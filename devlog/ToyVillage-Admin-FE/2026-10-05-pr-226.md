## 요약
Sentry에 수집되는 API 오류의 심각도를 HTTP 상태 코드에 따라 분류하여 기록하도록 개선했습니다. 404 및 409 오류는 경고(Warning) 수준으로, 405 오류는 에러(Error) 수준으로 수집하며 취소된 요청 등은 제외 처리했습니다. 변경 사항이 올바르게 동작하는지 확인하기 위한 E2E 테스트 코드도 함께 추가했습니다.

## 변경 내용
- **Sentry 에러 리포팅 세분화 (`src/shared/api/reportApiError.ts`)**:
  - HTTP 404, 409 상태 코드는 경고(Warning) 등급으로 Sentry에 전송하도록 변경했습니다.
  - HTTP 405 상태 코드는 에러(Error) 등급으로 전송하도록 처리했습니다.
  - 취소된 요청(Cancelled requests)이나 수집 대상이 아닌 응답은 기록에서 제외했습니다.
  - 응답이 전혀 없는 요청의 경우, 사용자가 온라인 상태이고 화면이 활성화(Visible)된 상태일 때만 에러로 기록하도록 예외 처리를 추가했습니다.
- **E2E 테스트 추가 (`tests/e2e/sentry.spec.ts`)**:
  - API 요청 시 404 및 409 응답이 발생했을 때 Sentry에 정상적으로 수집되는지 검증하는 테스트 시나리오를 작성했습니다.

## 의도
모든 API 예외 상황을 동일한 심각도의 에러로 수집하게 되면 불필요한 알림 노이즈(Alert Fatigue)가 발생할 수 있습니다. 비즈니스 로직 상 발생 가능한 4xx 대 에러(404, 409 등)를 경고 등급으로 분류하고, 더 치명적인 문제(405 등)와 구분하여 모니터링의 효율성을 높이고자 했습니다.
