# 2026-09-20

## 요약
휴관일 삭제 기능 수행 시, 서버 측에서는 정상 처리되었음에도 화면에서 삭제 실패 오류가 표시되던 버그를 수정했습니다. 불필요하게 엄격했던 API 응답 본문의 형식 검증을 완화하고, HTTP 2xx 응답 상태 코드를 기준으로 성공 여부를 판정하도록 개선했습니다. 이와 함께 삭제 성공 시 화면에서 카드가 올바르게 사라지는지 검증하는 E2E 테스트를 추가했습니다.

## 변경 내용
- 휴관일 삭제 API(`closeScheduleApi.ts`)에서 불필요한 응답 본문(Response Body) 검증 로직을 제거하고, HTTP 2xx 응답 상태 코드를 정상 삭제 성공 기준으로 변경했습니다.
- 삭제 처리가 성공한 후 화면에서 해당 일정 카드가 즉시 제거되고 성공 토스트 메시지가 표시되도록 사용자 경험을 수정했습니다.
- 테스트 시나리오 및 E2E 테스트 코드에 휴관일 삭제 성공 시 화면상의 카드 요소가 정상적으로 제거되는지 검증하는 구문을 보강했습니다.

## 의도
서버가 삭제 처리를 무사히 마쳤음에도, 프론트엔드 측의 과도한 응답 검증으로 인해 "데이터 삭제에 실패했습니다"라는 잘못된 피드백을 전달하는 오작동을 해결하기 위함입니다. 응답 본문의 세부 형식에 의존하지 않고 HTTP 상태 코드로 직관적인 성공 판정을 내려 API 통신의 유연성과 안정성을 높였습니다.
