## 요약
대시보드와 종·개체 상세 페이지에서 영역별로 로딩 스켈레톤과 에러 처리를 분리하여 사용자 경험을 개선했습니다. 일부 API 호출이 실패하더라도 전체 화면이 차단되지 않고, 로드가 완료된 영역부터 순차적으로 정보를 확인할 수 있게 변경되었습니다. 또한, 영역별 조회 실패 처리를 위한 컴포넌트와 공통 헤더 및 스켈레톤 상태 제어 로직을 보완했습니다.

## 변경 내용
- **스켈레톤 및 에러 격리**: 대시보드 카드 단위, 종·개체 상세의 프로필 카드와 표 영역의 로딩/에러 상태를 독립적으로 분리했습니다.
- **오류 화면 분기 처리**: 프로필 조회 실패 시에는 화면 전체를 에러로 덮지 않고 프로필 영역에만 오류를 표시하며, 404 에러가 발생하는 경우에만 기존처럼 전체 화면에 `not-found`를 노출하도록 수정했습니다.
- **공통 컴포넌트 개선**: 중첩된 로딩 시 상태 알림이 반복되는 현상을 막기 위해 `SkeletonStatus` 처리를 개선하고, `SectionHeader`에 건수 로딩 상태를 보여주는 로딩 막대를 추가했습니다.
- **컴포넌트 리팩터링**: 기존 `ProfileDetailSkeleton`을 제거하고 목적에 맞춰 세분화한 `ProfileCardSkeleton`과 에러 표시용 `SectionError` 컴포넌트를 새로 도입했습니다.

## 의도
일부 데이터 조회 지연이나 특정 API 에러가 전체 페이지의 렌더링을 완전히 막아버리는 현상을 방지하기 위함입니다. 영역별로 로딩 및 에러 경계(Boundary)를 설정하여, 사용자가 준비된 데이터부터 먼저 확인하고 에러가 발생한 위치만 국소적으로 인지할 수 있도록 보장하고자 했습니다.
