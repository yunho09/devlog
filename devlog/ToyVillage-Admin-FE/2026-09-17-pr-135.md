# 2026-09-17

## 요약
Cloudflare Worker 배포 환경(`toyvillage-admin-fe-stag`)에 싱글 페이지 애플리케이션(SPA) 라우팅 지원을 위한 설정을 추가했습니다. `/login` 등 하위 경로로 직접 접속하거나 페이지를 새로고침할 때 발생하던 404 오류를 방지하고 `index.html`로 정상적으로 폴백(fallback)되도록 처리했습니다.

## 변경 내용
- Cloudflare Worker 배포 설정 파일인 `wrangler.jsonc`를 신규 생성하고 `toyvillage-admin-fe-stag` 배포 설정을 추가했습니다.
- `wrangler.jsonc` 파일에 `not_found_handling: "single-page-application"` 설정을 추가하여 SPA 경로 설정을 완료했습니다.
- `.gitignore` 파일을 수정하여 Wrangler 관련 로컬 설정이나 빌드 산출물이 버저닝에 포함되지 않도록 제외 규칙을 추가했습니다.

## 의도
React와 같은 SPA 환경에서는 브라우저 단에서 라우팅(CSR)을 처리하므로, 정적 서버 배포 시 임의의 하위 경로로 직접 접근하거나 새로고침을 하면 실제 해당 디렉터리나 파일이 존재하지 않아 서버가 404 에러를 반환하게 됩니다. 이를 방지하고 모든 경로 요청을 엔트리 포인트인 `index.html`로 포워딩하여 클라이언트 사이드 라우터가 정상적으로 동작하도록 구성하기 위함입니다.

## 트러블 슈팅
- **문제**: SPA 배포 환경에서 `/login`과 같은 하위 라우트로 직접 접속하거나 새로고침을 시도하는 경우, Cloudflare Worker가 해당 정적 리소스를 찾지 못해 404 에러가 발생하는 문제.
- **해결**: `wrangler.jsonc` 내에 `not_found_handling` 옵션을 `"single-page-application"`으로 지정하여, 리소스를 찾을 수 없을 때 서버가 404를 내려주는 대신 `index.html`을 반환하도록 유도함으로써 클라이언트 라우팅이 자연스럽게 이어지도록 처리함.

## 생각 정리
1. Cloudflare Workers 배포 환경에서 제공하는 `not_found_handling` 설정 외에, 로컬 개발 서버와 실제 배포 환경 간의 라우팅 동작 불일치를 미연에 방지하기 위해 로컬 테스트 단계에서 검증할 수 있는 방법은 무엇이 있을까?
2. JSON 형식을 사용하면서도 주석을 남길 수 있는 `wrangler.jsonc` 포맷의 이점을 활용하여, 추후 배포 환경별 세부 설정을 문서화할 때 어떤 구조로 주석을 관리하는 것이 협업에 유리할까?
3. 배포 인프라의 특성에 맞춰 라우팅 폴백 설정을 직접 구성하고 해결하는 과정에서, 프론트엔드 라우터와 정적 호스팅 서버 간의 유기적인 연동 과정에 대해 무엇을 느끼고 배웠는가?
