## 요약
공지사항의 분류 및 대상 지정을 기존 방식에서 팀 ID 목록(`teamIds`) 기반으로 전환한 작업입니다. 공지 생성 및 수정 시 여러 팀을 선택하여 발행할 수 있으며, 목록과 상세 화면에서는 응답받은 팀명을 올바르게 노출하도록 변경했습니다. 이에 맞춰 API 계약(Contract) 문서와 Mock 데이터, E2E 테스트 스펙을 일괄 갱신했습니다.

## 변경 내용
- **API 및 데이터 구조 변경**: 공지 생성/수정 요청 시 타겟팅할 팀을 `teamIds` 배열 형태로 전송하도록 수정했습니다.
- **UI 및 다중 팀 탭 연동**: 하나의 공지가 여러 팀에 지정되었을 때, 해당하는 모든 팀의 탭 필터에 노출되도록 필터링 로직을 개선했습니다. 팀 미선택 시에는 전체 공개로 처리됩니다.
- **오류 및 정보 표시 개선**: 공지 목록과 상세 화면에서 팀 ID에 대응하는 팀명을 올바르게 맵핑하여 표시하며, 존재하지 않는 팀을 지정했을 때의 에러 안내를 보강했습니다.
- **테스트 및 스키마 동기화**: Swagger 명세에 맞춰 API Contract 문서를 최신화하고, 대대적인 E2E mock 데이터 및 테스트 케이스 수정을 진행했습니다.

## 의도
공지사항을 특정 팀에 타겟팅하여 발행할 수 있도록, 기존의 분류 체계를 실제 서비스 내 팀 ID 체계(`teamIds`)와 동기화하기 위함입니다. 이를 통해 다중 팀 공지 발행 및 조회 기능의 데이터 정합성을 확보하고자 했습니다.
