# 2026-09-30

## 요약
Cloudflare 빌드 및 배포 과정에서 모노레포 구조로 인해 발생하던 빌드 실패 문제를 해결하고 배포 설정을 고도화했습니다. 루트 `package.json`의 빌드 스크립트를 재정의하여 개별 프로젝트 지정 없이도 전체 빌드가 가능하게 만들었으며, 각 서비스 앱에 `wrangler.jsonc` 설정을 추가하여 Workers 배포 및 SPA 폴백을 적용했습니다. 이와 함께 GitHub Actions 워크플로를 Pages 배포에서 Workers 배포에 맞춰 전반적으로 수정했습니다.

## 변경 내용
- **빌드 스크립트 수정**: 루트 `package.json`에서 `build` 스크립트를 `nx run-many -t build --parallel=3`으로 변경하여 인자 없이 실행 시 전체 프로젝트가 병렬 빌드되도록 수정했습니다.
- **새로운 빌드 스크립트 추가**: 기존 `nx build` 동작을 유지하기 위해 `build:app` 스크립트를 새롭게 정의했으며, 사용되지 않던 `build:many` 스크립트는 제거했습니다.
- **Wrangler 설정 파일 추가**: `apps/admin`, `apps/company`, `apps/student` 디렉터리에 각각 `wrangler.jsonc` 파일을 추가하여 정적 자산 서빙 및 SPA 라우팅을 위한 `not_found_handling: single-page-application` 설정을 적용했습니다.
- **배포 워크플로 변경**: GitHub Actions의 `deploy.yml` 및 `manual-deploy.yml`에서 Cloudflare Pages 배포 대신 Wrangler를 이용한 Workers 배포 방식으로 전환하고 관련 버그를 수정했습니다.
- **Worker 이름 규칙 정의**: Worker 이름을 `student-v2`, `admin-v2`, `company-v2`와 같이 앱을 명확히 구분할 수 있는 접미사 형식으로 지정했습니다.

## 의도
모노레포 환경에서 Cloudflare가 제공하는 기본 빌드 명령(`yarn run build`)이 인자 없이 호출될 때, Nx 환경에서 타겟 프로젝트를 찾지 못해 빌드가 실패하는 문제를 해결하기 위함입니다. 또한 각 앱별로 독립적인 SPA 라우팅이 원활하게 작동하도록 배포 환경을 표준화하는 목적이 있습니다.

## 트러블 슈팅
- **문제**: Cloudflare 빌드 단계에서 `NX Both project and target have to be specified` 에러와 함께 빌드가 실패하는 현상 발생. 원인은 루트 `package.json`의 `build` 명령이 `nx build`로 정의되어 있어, Cloudflare 빌드 봇이 인수 없이 이 스크립트를 호출할 때 대상 프로젝트를 지정하지 못해 실행이 중단됨.
- **해결**: 루트의 `build` 명령을 `nx run-many -t build --parallel=3`으로 변경하여 인수 없이도 전체 모노레포 앱들이 빌드되어 `dist/`에 결과물을 남기도록 수정했습니다. 기존 단일 빌드용 명령은 `build:app`으로 재배치하여 로컬 및 CI 파이프라인의 하위 호환성을 확보했습니다.
