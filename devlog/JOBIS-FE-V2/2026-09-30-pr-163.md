## 요약
`develop` 브랜치에 구성된 Cloudflare Workers 배포 설정을 `main` 브랜치에 반영하여 상용 배포 자동화를 구축한 PR입니다. `student-v2`, `admin-v2`, `company-v2` 세 개의 독립된 웹 애플리케이션이 `main` 머지 시점에 맞춰 고유한 Worker 환경으로 정상 빌드 및 배포되도록 구조를 개선했습니다.

## 변경 내용
- **빌드 스크립트 수정**: Cloudflare 기본 빌드 환경에서 인자 없이 실행할 때 실패하던 문제를 해결하고자 루트 빌드 명령을 `nx run-many -t build`로 전환했습니다.
- **개별 빌드 스크립트 추가**: 특정 앱만 빌드할 수 있는 `build:app` (`yarn build:app @jobis/<app>`) 명령을 `package.json`에 추가했습니다.
- **Wrangler 설정 도입**: `apps/admin`, `apps/company`, `apps/student` 경로 아래에 각각 `wrangler.jsonc` 파일을 구성하여 고유 Worker 이름(`<app>-v2`) 및 SPA 폴백, 정적 자산 규칙을 정의했습니다.
- **GitHub Actions 워크플로 업데이트**: 기존 Cloudflare Pages 배포 방식에서 작성된 `deploy.yml`과 `manual-deploy.yml`을 Wrangler 기반의 Workers 배포 방식으로 개편했습니다.

## 의도
모노레포 내에 존재하는 3개의 개별 애플리케이션을 Cloudflare Workers 인프라 상에서 독립적이면서도 안정적으로 자동 배포하기 위함입니다. 빌드 도구인 Nx의 이점을 극대화하여 모노레포 빌드 실패 문제를 예방하고, 운영 환경에 맞춰 분리된 서브도메인 주소로 원활히 트래픽이 라우팅되도록 설정하는 데 목적이 있습니다.

## 트러블 슈팅
- **Cloudflare에서 기본 `yarn run build` 명령이 실패하는 문제**
  - **문제**: 인자 없이 실행되는 기본 빌드 프로세스가 모노레포 환경에서 원만히 동작하지 못하고 에러를 발생시켰습니다.
  - **해결**: 루트의 `build` 명령을 `nx run-many -t build`로 대체 지정하여 의존 관계에 맞는 병렬 빌드가 정상 수행되도록 수정했습니다.
- **배포 타겟 Worker 이름 충돌 및 인프라 매핑 문제**
  - **문제**: 초기 설정 단계에서 배포할 대상 Worker들의 구분명이 명확하지 않아 상호 충돌 우려가 있었습니다.
  - **해결**: 각 앱의 루트에 `wrangler.jsonc`를 만들고, 이름을 `student-v2`, `admin-v2`, `company-v2` 형식의 명확한 접미사로 분리 정의하여 해결했습니다.
