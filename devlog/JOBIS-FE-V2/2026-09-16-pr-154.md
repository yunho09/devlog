# 2026-09-16

## 요약
학생 애플리케이션에 신규 버그 제보하기 기능을 추가하고 마이페이지와 라우터를 연결했습니다. 서버 API 제약 조건에 맞춰 제목 20자, 본문 400자의 글자 수 제한을 적용하기 위해 디자인 시스템의 Input 컴포넌트를 확장했습니다. 아울러 레이아웃 너비 조정, 공지사항 상세 내 첨부파일명 폴백 처리 등 전반적인 사용자 UI/UX 편의 사항을 함께 보완했습니다.

## 변경 내용
- **버그 제보 화면 추가 및 연결**: 학생 앱 내에 버그 제보 페이지를 신규 제작하고 라우팅을 등록했으며, 마이페이지에서 버그 제보 페이지로 진입할 수 있는 경로를 연결했습니다.
- **글자 수 입력 제한 적용**: 서버의 유효성 검사 기준에 대응하여 제목 20자, 내용 400자 제한을 두었으며, 이를 지원하기 위해 디자인 시스템의 `Input` 컴포넌트에 `maxLength` 속성을 추가했습니다.
- **첨부파일 업로드 및 UI 보완**: 제보 내용 작성 시 첨부한 파일을 삭제할 수 있도록 `FileDownload` 컴포넌트의 삭제 버튼 이벤트를 구현했으며, 내용 입력란 크기를 5줄로 확대했습니다.
- **레이아웃 및 공지 상세 보완**: 메인 레이아웃의 전체 너비(full width)를 적용하고, 공지사항 상세 내 첨부파일명이 유실되지 않도록 폴백 처리를 적용하고 다운로드 경로를 보정했습니다.

## 의도
학생 사용자가 앱 이용 중에 겪는 불편함이나 에러를 원활하게 제보할 수 있는 공식적인 창구를 확보하기 위함입니다. 또한, 클라이언트 단에서 사전에 서버의 유효성 검사 범위(글자 수 제한)를 강제함으로써 에러 요청을 방지하고 디자인 시스템의 기본 필드를 보완하여 일관된 입력 처리를 구현하려 했습니다.

## 트러블 슈팅
- **디자인 시스템의 공용 Input 컴포넌트가 maxLength 속성을 받지 못하는 현상** → `Input.types.ts`와 `Input.tsx` 코드를 수정하여 `maxLength` 속성이 input 태그에 정상 투과되도록 타입을 확장하고 테스트 코드를 추가해 작동을 보증했습니다.
- **공지사항 다운로드 경로 매핑 시 첨부 파일 이름이 깨지거나 공백이 발생하는 등 식별 오류** → `utils/helpers.ts` 파일에 파일명 파싱 함수를 추가하고, 파일명이 없을 때 대체 가능한 폴백 명칭을 적용하여 첨부 파일 다운로드 유동성을 보장했습니다.
- **본문 입력 영역 크기가 좁아 여러 줄의 내용을 수정하고 검토하기 어려운 불편** → 입력 영역을 5줄(rows) 높이로 기본 제공하도록 스타일을 지정하여 시각적 불편함을 개선했습니다.
