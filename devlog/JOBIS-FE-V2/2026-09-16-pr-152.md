## 요약
학생 앱의 모집의뢰서 목록 및 상세 페이지 내 필터 기능과 URL 상태 동기화 로직을 개선했습니다. 필터 옵션을 상수화하고 쿼리 키 형식을 통일하여 데이터 관리의 일관성을 높였습니다. 또한, 드롭다운이 URL 상태 변화에 신속하게 반응하지 않던 문제를 제어형 컴포넌트 형태로 전환하여 해결했습니다.

## 변경 내용
- **모집의뢰서 상세 개선**: 모집분야를 "전체"로 렌더링하는 처리를 추가하고, 면접과정을 한글로 표시하도록 개선했습니다.
- **필터 상수화**: 모집의뢰서에 사용되는 필터 옵션들을 전역적으로 사용하기 쉽게 `utils/constants.ts`로 분리 및 상수화했습니다.
- **쿼리 파라미터 및 키 일관성 확보**: 상태 필터의 쿼리 파라미터를 수정하고, 기술스택 쿼리 키 형식을 kebab-case로 통일했습니다. 모집전 필터에는 `REQUESTED` 상태를 반영하도록 조정했습니다.
- **드롭다운 상태 제어 방식 변경**: 코드리뷰 피드백에 따라 URL 쿼리 상태가 변경될 때 필터 드롭다운이 실시간 동기화되도록 기존 `$defaultValue` 방식에서 `value` 방식으로 제어 로직을 변경했습니다.
- **프리페칭 키 일치**: 데이터 목록의 프리페치(Prefetch) 키를 실제 화면 UI 쿼리와 일치시켰습니다.

## 의도
학생들이 모집의뢰서를 탐색할 때 필터를 설정하거나 공유된 URL을 타고 들어왔을 때, 화면의 필터 UI가 실제 데이터 및 URL 상태와 어긋나지 않고 정합성을 유지하게 만들기 위함입니다. 또한 필터 관련 코드 구조를 정리해 유지보수성을 높이고자 했습니다.

## 트러블 슈팅
- **분야 변경 시 기술스택 드롭다운 UI 상태 미동기화 문제**
  - **문제**: URL 파라미터가 변경되어도 드롭다운 내부가 비제어 컴포넌트(`$defaultValue`) 형태로 선언되어 있어 화면상 필터 UI 상태가 즉각적으로 일치하지 않는 현상이 있었습니다.
  - **해결**: 컴포넌트의 속성을 `value` 기반 제어형 구조로 전면 수정하여 URL 상태 변동을 추적하고 렌더링이 확실히 동기화되도록 처리했습니다.
