# 2026-09-16

## 요약
어드민 관리자 서비스 내 공지사항의 상세 조회, 등록, 수정 기능을 퍼블리싱하고 라우터와 연동하였습니다. 리뷰 사항을 반영하여 웹 접근성을 보완하였으며, 공지사항 상세 조회 실패 시 수정 기능을 사전에 차단하고 빈 폼이 노출되는 등의 오류 상황을 예방했습니다. 추가로 API 요청 시 403 에러에 대응하는 토큰 재발급 핸들러와 첨부파일 다운로드 경로 보정 헬퍼를 추가하였습니다.

## 변경 내용
- **공지사항 관련 신규 페이지 구현**: 공지사항 상세 조회(`detail`), 수정(`edit`), 등록(`write`) 페이지와 연동될 각각의 라우터 loader 및 page 컴포넌트 추가
- **웹 접근성(A11y) 개선**: 공지 상세 뷰 내 수정/삭제 아이콘을 `aria-label`이 지정된 `button`으로 감싸고, 목록 테이블 셀의 키보드 초점을 전체 행 대신 제목 `Link` 엘리먼트로 제한
- **예외 처리 강화를 통한 데이터 왜곡 방지**: 수정 페이지 진입 시 원본 데이터 조회에 실패하는 경우, 빈 폼을 보여주며 발생할 수 있는 비정상적인 `PATCH` 요청을 원천 차단하고 에러 화면 노출
- **인증 토큰 핸들링 수정**: `packages/api/src/instance.ts` 내에서 403 에러 발생 시 무한 재발급 루프에 빠지는 재시도 로직을 제거하고, 토큰 만료로 인한 403 코드를 재발급 대상에 명확하게 명시
- **파일 첨부 기능 강화**: 공지사항 등록 시 `FileUpload` 컴포넌트 및 첨부파일 제거 이벤트를 연동하고, 첨부파일 다운로드 경로와 파일명을 가공하기 위한 `utils/helpers.ts` 헬퍼 추가
- **기타 레이아웃 개선**: 공지 폼 입력 칸 위치 및 라벨의 폭과 간격을 디자인 시안에 맞게 일치시키고, 상세·수정 로더의 prefetch 대기 제거를 통한 페이지 진입 성능 개선

## 의도
PR 정보 기준으로 이번 변경은 관리자가 안전하게 공지사항을 등록하고 편집 및 조회할 수 있도록 필수적인 페이지들을 라우팅 구조 내에 빌드하기 위함입니다. 코드 리뷰를 수용하여 조회가 차단되거나 유효하지 않은 데이터가 전송될 위험을 방지하고, 시각 장애인 및 보조 기기 사용자를 고려한 마크업 및 초점 영역 정리를 통해 사용자 경험과 유효성 검증을 개선하고자 하였습니다.

## 트러블 슈팅
- **상세조회 실패 시 폼 공백 상태로 PATCH 요청 가능성** → 상세 정보 조회 API가 에러를 반환했음에도 화면에 빈 폼을 그리고 수정을 시도할 경우, 비정상적인 데이터가 백엔드로 전송될 수 있었습니다. 이를 수정 조회 실패 시 실패 화면을 우선 렌더링하고 `PATCH` 요청 전송을 강제 차단하여 데이터 무결성을 보호했습니다.
- **403 Forbidden 시 무한 루프 위험 및 토큰 재발급 오류** → API 호출 중 403 에러가 발생하는 경우 토큰 재발급 로직 내에서 계속해서 API를 재시도하는 위험이 있었습니다. 이를 방지하고자 재시도 코드를 명시적으로 제거하고, 대신 토큰 만료 케이스를 403 대응 범주에 명확히 통합하여 안정성을 높였습니다.
- **공지사항 첨부파일의 경로 유실과 비정상 파일명 가공** → 서버 파일 업로드 완료 후 제공되는 응답과 UI에 렌더링할 로컬 명칭이 불일치하거나 경로 다운로드 시 파일명이 깨질 수 있는 우려가 있었습니다. 이를 `utils/helpers.ts` 파일에서 경로와 파일명을 보정해주는 별도의 정제 로직을 구현하여 보완했습니다.
