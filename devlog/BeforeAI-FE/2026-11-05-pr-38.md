## 요약
Cloudflare Pages 배포 환경에서 교차 출처(Cross-Origin) 문제로 인해 새로고침 시 로그아웃되는 이슈를 해결한 PR입니다. Cloudflare Pages Function을 활용해 `/api/*` 요청을 백엔드로 전달하는 같은 출처(Same-Origin) API 프록시를 추가했습니다. 이를 통해 `SameSite=Strict` 리프레시 쿠키와 응답 스트림을 안전하게 포워딩할 수 있게 되었습니다.

## 변경 내용
- **API 프록시 구현**: Cloudflare Pages Function(`functions/api/[[path]].ts`) 및 프록시 로직(`src/api/pagesProxy.ts`)을 추가하여 `/api/*` 요청, 응답 스트림, `Set-Cookie` 헤더 포워딩
- **헤더 필터링**: 보안 및 망 판정 왜곡 방지를 위해 `X-Access-Network`, `X-Forwarded-For`, `X-Real-IP` 등의 클라이언트 망 헤더 전달 차단
- **테스트 및 설정**: `src/api/pagesProxy.test.ts` 단위 테스트 5개 추가, `.env.example` 및 `README.md`에 Pages 프로덕션 환경 변수(`API_PROXY_TARGET`) 안내 추가

## 의도
`swunion.pages.dev` 도메인과 백엔드 API 도메인이 달라 브라우저의 `SameSite=Strict` 정책에 의해 리프레시 쿠키가 전송되지 않던 문제를 해결하기 위함입니다. 동일 출처 경로(`/api/*`)로 요청을 캡처해 백엔드로 프록시 처리함으로써 로그인 상태가 새로고침 후에도 유지되도록 구현했습니다.
