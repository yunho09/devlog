- 레시피 API 함수와 응답 타입 추가 (`src/api/recipe.ts`)
  - 추천 `POST /api/fridges/{fridgeId}/recipes/recommendations`, 상세 `GET /api/recipes/{recipeId}`
  - 타입은 백엔드 `RecipeResponse` 기준. AI가 주지 않을 수 있는 값(이모지, 요약, 조리 시간, 난이도, 인분, 칼로리, 분량, 영양 정보)은 `null`로 받고 화면에는 `-`로 표시
- 냉장고 조회 API 함수 추가 (`src/api/fridge.ts`) ⚠️ **백엔드에 아직 없는 API**
  - `GET /api/fridges` (내가 속한 냉장고 목록), `GET /api/fridges/{fridgeId}/items` (냉장고 재료 목록)
  - 필드는 ERD(`fridges`, `fridge_members`, `fridge_items`) 기준으로 맞췄고 주소는 가정. 백엔드 API가 나오면 이 파일만 맞추면 된다
  - 공유 냉장고에 함께 속해 있어도 내가 OWNER인 냉장고를 먼저 쓴다
- 레시피 추천 화면
  - 내 냉장고를 불러온 뒤 "AI 추천 생성"으로 추천을 요청하고, "임박 재료 우선 사용" 값을 함께 보낸다
  - 냉장고 불러오기·추천 중에는 스켈레톤, 실패하면 서버 메시지와 다시 시도 버튼, 결과가 없으면 빈 상태 안내
  - `NO_USABLE_INGREDIENT`면 "냉장고 확인하기"로 냉장고 화면에 보내고, `FRIDGE_NOT_FOUND`면 냉장고부터 다시 불러온다
  - 추천에 실패해도 이전 추천 목록은 오류 안내 아래에 그대로 둔다
- 임박 재료 패널 (`UrgentIngredientList.tsx`): 냉장고 재료 중 오늘~D-5인 재료를 가까운 순서로 5개까지 (Bium-v1과 같은 기준)
- 레시피 상세 화면: 주소의 id로 불러오고 로딩·오류(다시 시도)·없는 레시피(404, 숫자가 아닌 id) 표시
- 추천 결과 스토어 (`src/store/recipeStore.ts`)
  - 지난 추천 목록 API가 없어서 마지막 추천 목록을 localStorage에 저장한다. 상세 화면에 다녀오거나 새로고침해도 남는다
  - fridgeId가 같을 때만 보여 주고, 로그아웃·토큰 만료 시 지운다
  - 추천 진행 상태도 스토어에 둬서, 추천 중에 다른 화면에 다녀와도 버튼이 잠긴 채라 AI 요청이 중복되지 않는다 (진행 상태는 저장하지 않음)
- 레시피 목데이터(`recipeMockData.ts`), 퍼블리싱용 타입(`recipeTypes.ts`), `?preview=` 확인용 코드 삭제
- 카드·상세의 배경색을 목록 순서 대신 레시피 id로 정해 두 화면 색이 항상 같게 함

- Sprint 1의 AI 레시피 서버 이전에 맞춰, 레시피 화면을 백엔드 추천·상세 API에 연결한다.
