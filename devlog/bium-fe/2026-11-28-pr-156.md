# 2026-11-28

## 요약
공유 화면에서 활동 기록을 커서 기반으로 이어서 불러오는 "더 보기" 기능을 구현했습니다.
백엔드 API 변경(bium-be #135)에 맞추어 `{ activities, nextCursor }` 응답 구조를 처리하고, 연속된 페이지 간 요리 기록 묶기 및 데이터 갱신 시 상태 동기화를 보완했습니다.
불러오는 도중 중복 요청 방지, 실패 시 재시도 UI 처리, 첫 페이지 갱신 후 이전 불러온 기록과의 안전한 연결 검증 로직을 포함합니다.

## 변경 내용
- `src/api/fridgeShare.ts`: `getActivities` API 함수에 `cursor` 파라미터를 추가하고, 백엔드의 `{ activities, nextCursor }` 응답 형식을 받도록 수정
- `src/components/Share/ActivityPanel.tsx`: 활동 기록 목록 하단에 "더 보기" 버튼 추가, 로딩 중 중복 요청 방지, 실패 시 오류 문구 및 "다시 시도" 버튼 노출, 모든 데이터 수신 완료 시 버튼 숨김 처리
- `src/components/Share/SharePage.tsx`: 내보내기 및 되돌리기 수행 후 1페이지를 다시 불러올 때 기존에 이어서 불러온 데이터와의 연결 지점을 검증하여 유지하거나 재조정하는 로직 추가

## 의도
백엔드 API 변경(bium-be #135)에 맞춰 활동 기록을 커서 기반 페이징으로 불러오도록 변경하기 위함입니다.
이전 develop 브랜치에서는 백엔드의 변경된 객체 응답 대신 배열 응답을 기대하고 있어 활동 기록이 정상 렌더링되지 않던 이슈를 해결하고, 더 보기 기능을 통해 대용량 기록을 효율적으로 조회할 수 있도록 개선했습니다.

- `src/api/fridgeShare.ts`: 활동 기록 조회 API에 cursor 쿼리 파라미터 추가 및 백엔드 응답 타입 구조 반영
- `src/components/Share/ActivityPanel.tsx`: "더 보기" 버튼 UI, 중복 요청 방지, 실패/재시도 상태 처리, 페이징 간 요리 기록 묶기 렌더링 적용
- `src/components/Share/SharePage.tsx`: 더 불러오기 상태 및 커서 관리, 1페이지 재요청 시 기존 이어서 불러온 기록과의 안전한 재연결/검증 처리

## 트러블 슈팅
- 문제: 백엔드 API 응답 방식이 `{ activities, nextCursor }` 객체 구조로 변경되어, 기존에 배열 구조를 기대하던 프론트엔드에서 활동 기록이 렌더링되지 않는 문제 발생 → 해결: `getActivities` API 및 관련 컴포넌트의 데이터 수신 타입을 커서 기반 응답 구조에 맞게 수정
- 문제: 내보내기/되돌리기 동작 후 첫 페이지를 다시 불러올 때, 이미 "더 보기"로 이어서 불러와 둔 데이터의 연결 지점이 불일치하거나 갭(gap)이 생길 수 있는 위험 → 해결: 첫 페이지의 마지막 기록 뒤에 기존 이어서 불러온 기록이 제대로 연결되는지 확인하고, 연결 지점을 찾지 못하거나 상태가 바뀌었으면 추가 페이지를 버리고 첫 페이지만 유지하도록 안전장치 구현
