# 2026-11-28

## 요약
액세스 토큰 만료 시 리프레시 토큰을 이용해 로그인을 자동으로 유지하는 기능을 구현했습니다. API 요청 중 401 응답이 발생하면 중복 및 다중 탭 요청을 고려해 단 1회의 토큰 재발급 요청만 처리하도록 제어 로직을 추가했습니다. 토큰 갱신 시에도 동일 세션임을 식별할 수 있도록 `sessionId` 개념과 `authStore` 마이그레이션 구조를 도입했습니다.

## 변경 내용
- `authStore`에 `refreshToken`, `sessionId` 저장 구조 추가 및 `version: 1` 마이그레이션 로직 구현
- `api/client.ts`에 401 에러 발생 시 `POST /api/auth/refresh`로 새 토큰을 받아 원래 요청을 재시도하는 인터셉터 추가
- 동시 401 요청 처리 단일화 및 Web Locks API를 사용한 다중 탭 환경 내 단일 갱신 보장
- 갱신 실패(400/401) 시 인증 정보 삭제 및 로그인 만료 안내, 네트워크 에러나 5xx 응답 시에는 로그인 상태 유지
- 로그아웃(`POST /api/auth/logout`) 연동으로 서버의 리프레시 토큰 무효화 처리
- 비동기 응답의 유효성 검증 타당성을 위해 `accessToken` 비교 기준을 로그인 시 생성되는 `sessionId` 비교로 교체

## 의도
액세스 토큰이 만료되었을 때 사용자가 매번 다시 로그인해야 하는 불편을 해결하고 로그인 상태를 안전하게 연장하기 위함입니다. 또한 토큰 재발급은 계정이 변경된 것이 아니므로, 기존의 토큰 비교 기반 비동기 응답 버림 로직을 `sessionId` 기반으로 교체하여 올바른 세션 추적이 가능하도록 개선했습니다.
