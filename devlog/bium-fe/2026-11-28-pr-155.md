## 요약
헤더의 로그아웃 버튼을 닉네임 기반 계정 메뉴로 대체하고, 닉네임 변경이 가능한 계정 설정 화면(`/account`)을 추가했습니다.
헤더와 계정 페이지에서 동일한 사용자 프로필 정보를 참조할 수 있도록 `profileStore`를 구현했습니다.
계정 전환 시 이전 요청의 응답이 늦게 도달하여 상태가 꼬이는 비동기 레이스 조건과 닉네임 저장 시의 중복 요청을 방지했습니다.

## 변경 내용
- **헤더 계정 메뉴 추가**: `AppHeader` 내 기존 로그아웃 버튼을 닉네임 첫 글자가 표시되는 계정 버튼(`AccountMenu`)으로 변경. 클릭 시 닉네임/이메일 정보, 계정 설정 페이지 링크, 로그아웃 메뉴 드롭다운 제공.
- **계정 설정 화면 추가**: `/account` 경로에 이메일 조회 및 닉네임 변경(2~10자, 앞뒤 공백 제거) 기능이 포함된 `AccountPage` 및 `ProfileForm` 구현.
- **API 연동**: `src/api/user.ts`에 사용자 프로필 조회(`GET /api/users/me`) 및 닉네임 수정(`PATCH /api/users/me/nickname`) API 추가.
- **상태 관리 (`profileStore`)**: 전역 사용자 상태 관리 스토어 신설. 헤더와 설정 화면 간 프로필 상태 공유, 로그아웃/계정 변경 시 스토어 초기화 및 지연 수신된 이전 계정 응답 파기 기능 반영 (`localStorage` 미저장).
- **상태 및 중복 요청 처리**: 프로필 로딩 및 실패 시 재시도 UI 제공, 닉네임 저장 처리 중 저장 버튼 비활성화.

## 의도
사용자가 본인의 계정 정보를 직관적으로 확인하고 닉네임을 직접 관리할 수 있는 UI/UX를 제공하기 위해 변경되었습니다. 또한 전역 상태 스토어를 신설하여 컴포넌트 간 프로필 데이터 불일치를 방지하고, 계정 전환이나 네트워크 지연 환경에서 발생할 수 있는 비동기 데이터 꼬임 현상을 방지하고자 했습니다.
