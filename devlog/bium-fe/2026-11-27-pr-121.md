## 요약
도감 페이지에서 도감 목록과 냉장고·장본 음식 데이터를 `Promise.all`로 묶어 호출하던 구조를 분리했습니다. 냉장고나 장본 음식 API 호출이 실패하더라도 도감 목록은 정상적으로 조회 및 조작이 가능하도록 개선했습니다. 또한 `GroceryBag` 패널 내에 데이터 호출 실패 시 개별적으로 "다시 시도"할 수 있는 오류 UI를 추가했습니다.

## 변경 내용
- `LibraryPage.tsx`에서 `Promise.all`로 묶여 있던 도감 목록(`getMyCatalog`)과 냉장고·장본 음식(`getMyFridge` → `getPurchasedItems`) 호출을 독립된 `useEffect` 및 상태(`CatalogState`, `GroceryState`)로 분리
- 도감 데이터가 로드되면 냉장고/장본 음식 로드 실패와 상관없이 도감 재료 조회, 추가, 삭제, 즐겨찾기 기능을 사용할 수 있도록 수정
- `fridgeId`가 없는 동안에는 장본 음식 담기 및 냉장고에 넣기 버튼을 비활성화 처리
- "연결된 냉장고가 없어요" 안내 문구가 불러오기 실패와 오인되지 않도록, 냉장고 조회가 성공한 후 실제로 데이터가 없을 때만 노출되도록 변경
- `GroceryBag.tsx` 패널에 장본 음식 데이터 불러오기 실패 시 에러 메시지 및 패널 내 "다시 시도" 버튼 추가 (동일 패널 재요청 가능)

## 의도
냉장고/장본 음식 API의 일시적 오류나 실패 때문에 도감 전체 화면이 에러 페이지로 전환되는 과도한 결합을 해제하고, 부분적 실패 상태에서도 가능한 기능을 사용자에게 제공하여 회복탄력성(Resilience) 있는 UX를 구축하기 위함입니다.
