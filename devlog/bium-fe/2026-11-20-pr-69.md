# 2026-11-20

## 요약
앱 헤더에 로그아웃 버튼을 추가하고, 이미 로그인한 사용자가 `/` 또는 `/login` 경로에 진입할 경우 냉장고 페이지로 이동하도록 인증 가드(`RedirectIfAuth`)를 추가했습니다. 백엔드에 로그아웃 API가 없는 JWT 환경에 맞춰 클라이언트 측 토큰 및 관련 스토어 상태를 초기화하도록 구현했습니다. 버튼 추가에 따른 특정 화면 폭에서의 헤더 레이아웃 넘침 이슈도 함께 수정했습니다.

## 변경 내용
- **로그아웃 버튼 추가 (`AppHeader.tsx`)**: 헤더 우측에 로그아웃 아이콘 버튼(`aria-label="로그아웃"`)을 배치하고 클릭 시 로컬 토큰 삭제 후 로그인 화면으로 이동시켰습니다.
- **헤더 반응형 레이아웃 수정 (`AppHeader.tsx`)**: 44px의 로그아웃 버튼 공간 확보를 위해 우측 영역 너비를 확장(170px → 214px, 1000~1200px 구간은 120px → 164px)하고, 1000~1200px 구간의 간격을 16px에서 8px로 줄여 메뉴 넘침을 방지했습니다.
- **인증 사용자 리다이렉트 가드 구현 (`RedirectIfAuth.tsx`, `routes.tsx`)**: 로그인 상태에서 `/` 및 `/login` 접근 시 `/fridge`로 보냅니다. 로그인 제출 시 이중 이동을 막기 위해 화면 최초 진입 시점의 인증 상태만 판별하도록 구성했습니다.
- **주석 정비 (`recipeStore.ts`)**: 변경된 인증 흐름 동작에 맞춰 주석 내용을 수정했습니다.

## 의도
- 기존에는 401 에러 수신 시에만 토큰이 지워져 수동 로그아웃이 불가능했고, 동일 브라우저 사용 시 이전 사용자의 계정에 계속 접근 가능한 문제가 있었습니다.
- 백엔드 로그아웃 API가 따로 없는 JWT 구조이므로 프론트엔드에서 저장된 토큰을 지우고, 관련 스토어들이 상태 변화를 감지해 내부 데이터를 초기화하도록 처리했습니다.
