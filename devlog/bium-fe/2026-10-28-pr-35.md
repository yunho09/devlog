## 요약
만들고 싶은 음식 이름을 입력받아 레시피를 추천받고, 부족한 재료를 장보기 목록에 선택하여 담는 기능을 구현했습니다. 부족 재료 출처(`MISSING`) 태그 표시 및 선택 담기 확인 모달(`MissingIngredientModal`)을 추가했습니다. 선행 작업 커밋이 포함되어 헤더 냉장고 전환 기능 및 냉장고 공유 페이지 퍼블리싱도 함께 머지되었습니다.

## 변경 내용
- **만들고 싶은 음식 레시피 API 및 폼 구현**: `POST /api/fridges/{fridgeId}/recipes/target` API 연동 함수 추가 및 `/recipes` 화면에 입력 폼(`TargetRecipeForm`) 구현 (50자 제한, 앞뒤/전각 공백 제거, 로딩 중 읽기 전역 처리 및 400/422/429/502/503 에러별 처리).
- **부족 재료 표시 및 모달 구현**: 레시피 상세 화면에 부족 재료 태그('부족', 핑크색) 및 동일 재료 이름 병합 로직 추가. 부족 재료 선택 후 `POST /api/recipes/{recipeId}/shopping-list-items`로 담는 확인 모달(`MissingIngredientModal`) 추가.
- **냉장고 전환 및 공유 기능**: 헤더 내 냉장고 전환 스위처(`FridgeSwitcher`) 및 초대 코드로 참여하기 기능, 냉장고 공유 페이지(`SharePage`) 및 구성 컴포넌트 추가.

## 의도
- 사용자가 냉장고 보유 재료 외에 특정 요리에 필요한 부족한 재료를 쉽게 확인하고 구매할 수 있도록 지원하기 위함입니다.
- 공유 장보기 목록에 불필요한 재료가 무분별하게 추가되는 것을 방지하기 위해 사용자가 확인 모달에서 체크한 재료만 선택적으로 추가하도록 설계했습니다.

## 트러블 슈팅
- **음식 이름 입력 시 400 에러 처리 구분 문제** → 에러 코드가 나뉘어 오는 400 에러들에 대해 세부 에러 코드 대신 HTTP 400 상태 코드로 판단하여 '다시 시도' 버튼을 노출하지 않고 입력창 고침 상태로 유도하도록 해결.
- **냉장고 전환 시 레시피 생성 완료 안내가 노출되는 문제** → 레시피 생성을 요청한 냉장고 ID를 저장해두고, 현재 활성화된 냉장고와 일치할 때만 완료 안내 문구가 표시되도록 해결.
- **비동기 요청 응답의 순서 차이로 인해 완료 안내 문구가 지워지는 문제** → 새 요청이 시작되거나 지연된 이전 응답이 도달하더라도 완료 상태 표시를 함부로 덮어쓰지 않도록 상태갱신 조건 로직 수정.
- **320px 모바일 화면에서 레이아웃이 깨지는 문제** → 320px 응답형 환경에서 입력칸이 영역 밖으로 밀리던 이슈를 CSS/레이아웃 수정으로 해결.
