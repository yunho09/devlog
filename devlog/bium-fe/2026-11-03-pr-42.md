## 변경 내용
- `IngredientEditModal.tsx`: 아이콘 및 유통기한 필드를 비워둔 상태로 저장할 수 있도록 수정하고, 날짜 입력이 미완성된 경우 저장을 막는 유효성 검사 로직을 추가했습니다.
- `FridgePage.tsx`: 수정 모달에서 저장을 실행할 때 빈 값을 `null`로 변환하여 백엔드로 전달하고, 서버 응답 데이터로 화면을 갱신하도록 처리했습니다.
- 유통기한을 지우고 저장할 경우 카드 UI의 D-Day 배지가 정상적으로 제거되도록 처리했습니다.

## 의도
영수증 확인 화면에서는 유통기한이나 아이콘이 없는 상태로 재료를 추가할 수 있었으나, 기존 수정 모달에서는 두 값이 필수 입력 조건이었습니다. 이로 인해 유통기한이나 아이콘이 없는 재료는 이름만 변경하려 해도 저장할 수 없는 불일치가 발생했습니다. 백엔드 API(`PUT /api/fridge-items/{itemId}`)는 이미 `null` 값을 허용하고 있었으므로 프론트엔드의 저장 제약 조건을 완화하였습니다.

## 트러블 슈팅
- 문제: 유통기한을 수정할 때 날짜를 완전히 지우지 않고 덜 입력한(미완성) 상태에서도 저장 동작이 유효한 것으로 처리될 수 있는 가능성이 있었습니다.
- 해결: 날짜가 미완성되었거나 유효하지 않은 입력 형태일 때는 안내 문구를 띄우고 저장을 막아, 날짜를 완전히 채우거나 완전히 지웠을 때만 저장이 가능하도록 처리했습니다 (`227121a`).
