JPA Auditing 기반의 `BaseTimeEntity`와 공통 에러 응답 처리 구조를 구축했습니다. `GlobalExceptionHandler`와 `ErrorCode`, `ErrorResponse`를 신설하여 유효성 검사 실패, 잘못된 요청, Redis 장애 등에 대해 일관된 JSON 에러 응답을 반환하도록 구현했습니다. 또한 Redis 연결 타임아웃 설정을 추가하여 서비스 불능 시 신속하게 503 응답을 반환하도록 개선하고 관련 전역 예외 처리 테스트 코드를 추가했습니다.

- 예외 처리 검증을 위한 `GlobalExceptionHandlerTest` (10개 테스트 케이스) 작성
- CodeRabbit 자동 리뷰 설정 파일(`.coderabbit.yaml`) 추가

엔티티의 생성 및 수정 시각을 자동화하고, 전역 예외 처리 체계를 구축하여 API 응답 규격을 통일하기 위해 작업했습니다. 또한 Redis 미응답 시 지연 시간을 단축(실측 60초 → 2초)하여 빠른 503 응답처리를 도모하고, `@WebMvcTest` 수행 시 JPA metamodel 관련 슬라이스 테스트 실패를 방지하고자 설정 클래스를 분리했습니다.

## 트러블 슈팅
- 메인 클래스에 `@EnableJpaAuditing`을 선언했을 때 `@WebMvcTest` 기반 컨트롤러 테스트에서 `JPA metamodel must not be empty` 에러 발생 → `@EnableJpaAuditing`을 메인 클래스가 아닌 독립된 `JpaAuditingConfig` 설정 클래스로 분리하여 해결
- Redis 장애 시 응답이 오지 않아 응답 대기 시간이 60초까지 지연되는 문제 → `application.yml`에 `spring.data.redis.timeout` 및 `connect-timeout`을 2초로 설정하여 2초 만에 503 에러 응답을 반환하도록 개선
- 에러 응답 반환 시 클라이언트 오류 상태코드가 유실되거나 Content-Type이 JSON으로 지정되지 않는 문제 → 핸들러에서 상태코드를 유지하고 `Allow` 헤더 및 JSON Content-Type을 explicit하게 지정하도록 수정 (`ae95386`, `9d55cf0` 커밋)
