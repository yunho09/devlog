## 요약
Spring Security와 JWT 기반의 인증 및 인가 인프라를 구축하고 회원(`User`) 및 리프레시 토큰(`RefreshToken`) 엔티티를 설계했습니다.
인증 공통 예외 처리와 함께 Redis 및 Lua 스크립트를 활용한 로그인 실패 잠금, 요청 제한(Rate Limit), 이메일 검증 토큰 발급 서비스를 구현했습니다.
또한 Testcontainers(MySQL, Redis)를 도입하여 로컬 환경과 독립적인 통합 테스트 환경을 마련하고 보안 및 동시성 관련 문제를 보완했습니다.

## 변경 내용
- `User` 및 `RefreshToken` 엔티티 추가 (이메일 `utf8mb4_bin` Collation 설정, 온보딩 상태 `VARCHAR` 매핑, 리프레시 토큰 SHA-256 해시 저장 및 Soft Delete 적용)
- Spring Security 설정(`SecurityConfig`) 및 JWT 관련 컴포넌트(`JwtAuthenticationFilter`, `JwtProvider`, `JwtAuthenticationEntryPoint`, `JwtAccessDeniedHandler`) 구현
- 인증 공통 에러 코드(`ErrorCode`) 및 Redis 연동 공통 서비스(`TokenService`, `VerificationTokenService`, `LoginAttemptService`, `RateLimitService`, `AuthRedisKeys`) 구현
- 프로젝트 루트 `.env` 연동 및 JWT 설정(`JwtProperties`) 추가
- Testcontainers 기반 static 컨테이너 선언 및 `IntegrationTestSupport` 통합 테스트 기반 클래스 구축

## 의도
이후 연관된 인증/인가 기능(회원가입, 로그인, 계정 연동 등)을 병렬로 개발할 때 발생할 수 있는 코드 충돌을 방지하기 위해 공통 모듈과 도메인 모델을 선제적으로 구현했습니다. 또한 Redis 동시성 제어 및 Testcontainers 도입으로 보안성과 테스트 안정성을 제고하고자 했습니다.

## 트러블 슈팅
- 스프링 컨텍스트가 닫힐 때 테스트 컨테이너가 같이 꺼져 다른 테스트가 실패하는 현상 → static 컨테이너 선언과 `@DynamicPropertySource`를 결합하여 수명주기를 JVM 단위로 고정해 해결
- 동시 요청으로 인해 로그인 5회 시도 제한을 우회하는 동시성 문제 → `LoginAttemptService.start()`에서 Redis Lua 스크립트를 사용해 잠금 확인, 시도 횟수 증가, 잠금 처리를 단일 원자적 명령으로 실행하여 해결
- 이메일 대소문자/악센트 차이로 DB 조회 결과와 Redis 로그인 잠금 키 기준이 일치하지 않는 문제 → `User.email` 컬럼 Collation을 `utf8mb4_bin`으로 지정하고 Redis 키 생성 시 소문자로 정문화하여 해결
- `.env.example`에 정의된 빈 값이 yml의 기본 설정을 덮어써 애플리케이션 시작에 실패하는 문제 → `.env.example` 내 기본값 사용 항목을 주석 처리하여 해결
- 비동기 응답 처리 중 재디스패치 시 인증 정보가 소실되어 401 에러가 발생하는 문제 → `RequestAttributeSecurityContextRepository`에도 SecurityContext를 저장하도록 수정하여 해결
