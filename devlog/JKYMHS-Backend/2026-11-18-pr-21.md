### 1. 목록 조회 SQL — `ContentSearchRepository`, `ContentSearchCondition`
- **왜 JdbcTemplate인가**: 탭·검색어·지역·카테고리·상태·칩 9종·지도 범위가 자유롭게 조합된다. JPA 파생 쿼리로는 조합마다 메서드가 필요하고, 이 프로젝트에는 QueryDSL이 없다. 그래서 조건마다 `WHERE` 조각과 파라미터를 같이 붙이는 작은 빌더(`Where`)를 만들고 `NamedParameterJdbcTemplate`으로 실행한다. 사용자 입력은 전부 `:name` 파라미터로만 들어가서 SQL 문자열에 섞이지 않는다.
- **키셋(keyset) 페이지네이션**: `ORDER BY 정렬값, name, id` + `WHERE (정렬값, name, id) > (커서 값)`을 풀어 쓴 조건 + `LIMIT size+1`.
  - OFFSET을 쓰지 않는 이유: OFFSET은 앞 페이지 행을 모두 읽고 버리므로 뒤로 갈수록 느려진다. 페이지를 넘기는 사이에 행이 추가·삭제되면 중복·누락도 생긴다.
  - 마지막에 항상 `id`를 붙이는 이유: 점수·이름이 같은 행이 있어도 순서가 하나로 정해져야 커서가 이어진다 (테스트 `popularCursorWithTie`).
  - #18이 만든 인덱스 `idx_contents_type_popularity (content_type, is_deleted, popularity_score, name, id)`, `idx_contents_type_name`, `idx_contents_type_sido_dates`가 이 정렬 순서와 같다.
- **목록은 id와 정렬 값만 읽는다**. 화면에 필요한 지역 이름·소분류 이름은 `ContentService.findSnapshots`가 한 번에 채운다 (`ContentItemAssembler`). 카드마다 조회하면 N+1 쿼리가 된다.
- **칩 조건** (`ContentChip`)
  - `ongoing`: 진행 중만 (status 파라미터보다 우선). `popular800`: 인기 점수 ≥ 800.
  - `weekend`: 축제 기간이 "다가오는 토·일"과 겹치는 것 (`시작 ≤ 일요일 AND 끝 ≥ 토요일`). 오늘이 토요일이면 [오늘, 내일], 일요일이면 [오늘]만이다 (지난 토요일은 이미 지났다).
  - `open_now`: 오늘이 쉬는 요일이 아니고(`FIND_IN_SET('MON', rest_days) = 0`) 지금이 운영 시간 안. 밤을 넘기는 영업(18:00~02:00, close ≤ open)은 "open 이후이거나 close 이전"으로 본다. #18의 `OpenStatusCalculator`와 같은 규칙이다.
  - `palace_village`·`museum_exhibit`·`view_park`·`with_kids`: `CategoryService.lclsCodesOf(칩 코드)`의 분류 코드가 lcls1/2/3 중 하나와 같으면 맞다. 어떤 분류가 들어가는지는 #18의 시드 표가 정한다.
  - `night`: 축제는 행사 시각 20시 이후, 장소는 닫는 시각 20시 이후 또는 자정을 넘기는 곳.
  - `all`: FE의 "전체" 칩. 거르지 않는다.
- **거리 검색**: 위도·경도 사각형(`BETWEEN`)으로 먼저 좁혀서 `(content_type, latitude, longitude)` 인덱스를 타고, 그 안에서만 `ST_Distance_Sphere(POINT(lng, lat), …)`로 실제 거리를 계산한다. 거리 계산만으로 거르면 모든 행을 계산하게 된다.

### 2. 목록 서비스 — `ContentExploreService`, `ContentSort`, `ContentChip`, `SearchKeyword`
- 요청 검증 → 조회 조건 만들기 → 키셋 조회 → 카드로 바꾸기 순서다. 탭에 맞지 않는 값(축제 탭의 `sort=name`, 관광지 탭의 `status`·`chip=ongoing`, 다른 탭의 카테고리)은 400 "잘못된 필터 값입니다."로 막는다.
- **검색어**(`SearchKeyword`): 글자·숫자·공백만 남기고 공백을 하나로 줄인 뒤 2자 미만이면 400 "검색어는 2자 이상 입력해주세요.". 특수문자를 지우면 LIKE의 `%`·`_`가 사용자 입력에서 와일드카드로 쓰이지 않는다.
- **커서**: `{t: 탭, s: 정렬, k: [정렬 값], i: id, v: 인기 점수 버전}`을 #16의 `CursorCodec`으로 base64url 인코딩한다. 다른 탭·정렬의 커서, 형식이 틀린 커서는 400 `INVALID_CURSOR`. 값을 하나씩 타입 확인해서 조작된 커서가 500이 되지 않게 했다.
- **인기순 커서 버전(409)**: 인기 점수 배치(D3, 1시간마다)가 점수를 다시 매기면 Redis `popularity:version`이 오른다. 그 전에 받은 커서로 이어 읽으면 점수가 바뀐 항목이 빠지거나 두 번 나오므로 409 `CURSOR_VERSION_MISMATCH`로 처음부터 다시 받게 한다. Redis를 못 읽으면 첫 페이지는 `v:0`을 넣고, 다음 페이지에서도 못 읽으면 비교를 건너뛴다 (캐시 장애로 목록이 막히지 않게, G12).
- **탭별 개수(counts)**: 첫 페이지에만 준다. 같은 검색어·지역·지도 범위에서 각 탭의 기본 상태(축제는 진행 중+예정)로 센다. 카테고리·칩·상태 필터는 탭 머리 숫자에 넣지 않는다.
- **비교 담기 조회**(`lookup`): 보낸 순서를 지키고 중복 id는 한 번만, 삭제됐거나 없는 id는 `missingIds`로 준다.

### 3. 자동완성 — `ContentAutocompleteService`
- 지역(이름 앞부분 일치, 최대 2개) + 장소·축제를 순위대로 섞어서 합계 10개.
- 순위 = 고른 지역 안(+2) + 이름이 검색어로 시작(+1) → 인기 점수 → id. 장소와 축제를 각각 "남은 칸 수"만큼 SQL로 읽은 뒤 같은 기준으로 합쳐서 남은 칸을 채운다. 한 종류가 칸을 다 차지하지 않고 더 잘 맞는 결과가 먼저 보인다.
- 끝난 축제는 뺀다. 지역은 280여 개라 `RegionService.getAllRegions()`를 메모리에서 거른다.

### 4. 상세 — `ContentDetailService` (7일 캐시·Redis 락·부분 실패)
- 소개글·사진은 CSV 초기 적재에 없어서 처음 볼 때 TourAPI에서 받아 저장하고, 7일(`content-detail.refresh-after`) 동안 저장된 값을 쓴다. 매번 부르면 하루 호출 한도(개발 키 1000회)를 금방 쓴다.
- **다시 받는 조건**: `content_details` 행이 없거나, `fetched_at IS NULL`(CSV·운영 정보로만 만든 행, #18 참고), 또는 7일이 지났을 때.
- **Redis 락**: `SET lock:detail:{id} <uuid> NX PX 10000`. 인기 콘텐츠를 여러 명이 동시에 열어도 TourAPI는 한 번만 부른다. 락을 못 잡은 요청은 기다리지 않고 저장된 값을 준다. 해제는 Lua 스크립트로 "내가 건 값일 때만 DEL" 한다. 갱신이 10초를 넘겨 락이 저절로 풀리고 다른 요청이 새로 건 락을 지워버리지 않기 위해서다. Redis가 안 되면 락 없이 갱신한다.
- **호출 순서와 부분 실패**: detailCommon2(소개글) → detailIntro2(운영 시간) → detailImage2(사진) → 반려동물 정보를 모를 때만 detailPetTour2. 소개글이 실패하면 아무것도 저장하지 않는다. 그 뒤가 실패하면 받은 데까지만 `ContentService.applyDetail`에 넘기고 나머지는 null(기존 값 유지)로 둔다.
- **TourAPI가 실패해도 200**: 저장된 상세가 있으면 그 값 + `isStale: true`, 없으면 기본 정보 + `detailAvailable: false` (FE가 상세 영역에 재시도 안내).
- **트랜잭션을 걸지 않은 이유**: 외부 호출(수 초) 동안 DB 커넥션을 잡지 않고, 갱신 뒤 다시 읽을 때 새 값이 보이게 하려고. 저장은 `applyDetail`이 자기 트랜잭션으로 한다.
- `contact`는 상세의 문의처가 없으면 콘텐츠의 `tel`을 쓴다.

### 5. 거리 API — `ContentNearbyService`
- 함께 가기 좋은 곳: 1km 안의 관광지 + 끝나지 않은 축제, 자기 자신 제외, 가까운 순 4곳. `walkMinutes = ceil(거리 / 67m)` (분속 67m ≈ 시속 4km).
- 주변 음식점·숙박: 기본 반경 음식점 1000m·숙박 3000m, 인기순 → 가까운 순, `totalCount`("주변 음식점 8곳 보기" 문구용)와 실제 쓴 `radiusMeters`를 준다. 0건이면 반경을 두 배로(최대 5000m) 한 번 더 찾는다.

### 6. 개인화 훅 — `ContentPersonalization`, `NoopContentPersonalization`
- 찜 여부(`liked`)·조회 기록은 로그인 기능(D3)의 몫이라 인터페이스로 떼어 두고 지금은 빈 구현(항상 false, 기록 안 함)을 쓴다. 컨트롤러는 `userId = null`을 넘긴다.
- D3가 Noop을 지우고 실제 빈을 등록한 뒤 컨트롤러에 `@AuthenticationPrincipal Long userId`를 붙이면 된다. 탐색 코드는 인터페이스만 알아서 고칠 곳이 컨트롤러 인자뿐이다.

### 7. 출발지 검색 — `domain/place` (카카오 로컬)
- `KakaoLocalClient`: 키워드 검색, 주소 검색, 좌표→주소. 헤더 `Authorization: KakaoAK {키}`, 타임아웃 3초(사용자가 화면에서 기다리는 요청). 키를 FE에 두지 않으려고 서버가 대신 부른다. `TourApiClient`처럼 `RestClient.Builder`를 생성자로 받아서 테스트에서 MockRestServiceServer를 붙인다.
- 검색: 키워드 결과("용산역") 뒤에 주소 결과("한강대로 405")를 붙이고, 이미 나온 주소는 뺀다. 최대 10개.
- 좌표→주소: 건물 이름 → 도로명 → 지번 순으로 이름을 정한다. **좌표는 저장하지 않고 로그에도 남기지 않는다** (PRD). `RestClientException` 메시지에는 요청 주소(x, y)가 들어 있어서 예외 종류·상태 코드만 남긴다.
- 키가 비었거나 카카오가 실패하면 502 `EXTERNAL_API_ERROR`(검색: "주소 검색에 실패했습니다. 다시 시도해주세요.", 좌표: "주소를 찾지 못했습니다. 다시 시도해주세요.").

### 8. 설정 — `application.yml`
- `kakao-local` (base-url, `rest-api-key: ${KAKAO_REST_API_KEY:}`, timeout 3s), `explore` (closing-soon-minutes 60, page-size-max 50), `content-detail` (refresh-after 7d, lock-ttl 10s). `@ConfigurationProperties` record로 읽는다 (`ExploreProperties`, `ContentDetailProperties`, `KakaoLocalProperties`).
- `.env.example`은 그대로다 (`KAKAO_REST_API_KEY` 줄은 #18에 이미 있다). `build.gradle`도 그대로다.
- 이 브랜치에는 `SecurityConfig`가 없어서 permitAll 규칙은 추가하지 않았다. D3가 `GET /api/contents`, `/api/contents/**`를 permitAll로 넣고, `/api/places/**`는 기본값(authenticated)으로 둔다.

## 확인 필요

- **상세 갱신이 요청 안에서 동기로 돈다**: TourAPI가 느리면 첫 조회가 느리다 (타임아웃 10초 × 재시도 3회가 최악). 락 TTL(10초)보다 오래 걸리면 다른 요청이 한 번 더 갱신할 수 있다. 실측해 보고 필요하면 "저장값을 먼저 주고 뒤에서 갱신"으로 바꾼다.
- **곧 마감(soon) 기준 60분**: FE 문서에 없어서 정했다 (`explore.closing-soon-minutes`).
- **자동완성은 이름만 본다** (목록 검색 `q`는 이름 또는 주소). 주소까지 보면 "서울"만 쳐도 결과가 너무 많아진다.
- **알 수 없는 enum 값**(`tab=beach`, `chip=xxx`, `status=DONE`)은 변환 단계 오류라 메시지가 "입력값이 올바르지 않습니다."다. 탭에 맞지 않는 값(검증 단계)만 "잘못된 필터 값입니다."다.
- **open_now·night 판단은 오늘 요일 기준**: 새벽 1시에 전날 밤 영업을 이어서 하는 곳도 "오늘"의 쉬는 요일로 본다 (#18 `OpenStatusCalculator`와 같다).
- **목록 검색은 `LIKE '%검색어%'`**: 데이터가 3만 건이라 지금은 충분하다. 느려지면 노션 제안대로 MySQL FULLTEXT(ngram)로 바꾼다.
- **출발지 검색 로그인 필수(401)**는 Security가 들어오는 D3 브랜치에서 확인한다.
