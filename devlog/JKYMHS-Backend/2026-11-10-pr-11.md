# 2026-11-10

## 요약
회원가입 및 로그인 API를 구현하고, 이와 관련된 보안 검증 및 로그인 시도 제한 로직을 추가했습니다. 이메일 인증 토큰 검증, 약관 동의 저장, BCrypt 암호화, 회원 저장 및 로그인 토큰 발급을 하나의 트랜잭션으로 처리했습니다. 또한, 타이밍 공격을 방지하기 위한 가짜 BCrypt 연산 수행, 계정 잠금(423), IP별 요청 제한(429) 기능을 도입했습니다.

## 변경 내용
- 약관 동의 엔티티(`UserConsent`) 및 Enum(`ConsentType`) 추가
  - 필수 및 선택 동의 항목 구분
  - Hibernate ENUM 매핑 문제 방지를 위해 `VARCHAR(30)` 타입으로 고정
- 회원가입 API (`POST /api/auth/signup`) 구현
  - 이메일 인증 토큰 검증 및 가입 완료 시 즉시 폐기
  - 이메일 정규화(`trim()`, `toLowerCase(Locale.ROOT)`) 및 비밀번호 정규식 검증
  - 약관 5종 동의 상태 저장 및 가입 즉시 로그인 토큰 발급
  - DB UNIQUE 제약 조건 예외 발생 시 409 응답 처리
- 로그인 API (`POST /api/auth/login`) 구현
  - 존재하지 않는 이메일과 비밀번호 불일치 시 동일한 401 응답 반환
  - 존재하지 않는 이메일 요청 시에도 가짜 BCrypt 비교를 수행하여 타이밍 공격 방지
  - 비밀번호 비교 전 시도 횟수를 먼저 기록하여 동시 요청을 통한 잠금 우회 방지
  - 5회 실패 시 10분간 계정 잠금(423), 구글 전용 계정 구분(409), IP 기반 요청 제한(429)
- 테스트 코드 작성 (`SignupApiTest` 16개, `LoginApiTest` 7개)

## 의도
사용자 인증의 핵심 기능인 회원가입과 로그인을 안정적이고 보안성 있게 제공하기 위해 진행된 변경입니다. 회원가입 시 회원 정보, 약관 동의, 토큰 발급을 단일 트랜잭션으로 묶어 반쪽짜리 데이터 생성을 방지했습니다. 로그인 시에는 계정 존재 여부 유출을 막는 보안 조치와 동시 로그인 시도 시의 Race Condition을 방지하는 로직을 적용했습니다.

## 트러블 슈팅
- **동시 가입 요청 시 이메일 중복 검사와 저장 사이에 끼어들어 DB 예외가 발생하는 문제** → DB UNIQUE 제약 조건(`uk_users_email`) 위반 시 발생하는 `DataIntegrityViolationException`을 캐치하여 500 에러 대신 409 응답으로 변환.
- **존재하지 않는 이메일 로그인 시 응답 속도 차이로 계정 존재 여부가 노출되는 문제(타이밍 공격)** → 존재하지 않는 이메일이라도 가짜 BCrypt 해시 비교 연산을 1회 수행하도록 하여 응답 시간을 일정하게 유지.
- **동시 로그인 요청 시 비밀번호 검증 전 시도 횟수를 세지 않아 계정 잠금을 우회할 수 있는 문제** → `LoginAttemptService.start()`를 BCrypt 검증 수행 전으로 이동시켜 로그인 시도를 먼저 기록하도록 수정.
- **Hibernate가 MySQL `ENUM` 컬럼으로 생성할 경우 향후 약관 항목 추가 시 기존 DB 저장이 실패하는 문제** → `@JdbcTypeCode(SqlTypes.VARCHAR)`를 적용하여 컬럼 타입을 `VARCHAR(30)`로 고정.
- **약관 동의 여부 전달 시 `boolean` 타입 사용 시 값 누락과 미동의 구분 불가 문제** → 요청 DTO 필드를 `Boolean` 객체 타입으로 선언하고 `@NotNull` 및 필수 항목에 `@AssertTrue` 검증 적용.
