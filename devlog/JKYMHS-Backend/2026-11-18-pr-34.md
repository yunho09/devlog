closes #31

## API
`POST /api/auth/password/reset` (로그인 필요 없음, `/api/auth/**` permitAll)

```json
{ "email": "user@example.com", "verificationToken": "…", "newPassword": "new12345" }
```

| 응답 | 언제 |
|---|---|
| 204 | 성공. 본문 없음 |
| 400 `INVALID_INPUT` | 새 비밀번호가 규칙(영문+숫자 8~20자)에 맞지 않음, 이메일·토큰 누락 |
| 401 `EMAIL_NOT_VERIFIED` | 토큰 없음·만료·이미 사용, 회원가입용 토큰, **가입하지 않은 이메일** |

FE 흐름: `POST /api/auth/email/send`(purpose `RESET_PASSWORD`) → `POST /api/auth/email/verify` → 받은 `verificationToken`으로 이 API 호출 → 로그인 화면.

## 동작 순서 (`AuthService.resetPassword`)
1. verificationToken 확인과 폐기. 가입 때와 같은 Lua 스크립트라 같은 토큰으로 두 번 재설정할 수 없다.
2. 이메일로 회원을 찾고 회원 행을 잠근다(`getByIdForUpdate`). 같은 회원의 비밀번호 변경·탈퇴와 겹치지 않게 하려는 것이다.
3. 새 비밀번호 저장.
4. 모든 기기 로그아웃(`TokenService.revokeAll`, 리프레시 토큰 전부 삭제).
5. 로그인 실패 기록 삭제(`LoginAttemptService.reset`). 5번 틀려 잠긴 계정도 새 비밀번호로 바로 로그인된다. Redis는 롤백되지 않아서 DB 작업이 다 끝난 마지막에 지운다.

## 꼭 알아야 할 점
- **가입 여부를 숨긴다.** 가입하지 않은 이메일도 토큰 오류와 응답 본문까지 같은 401이다(`VerificationTokenService.notVerified()`를 같이 쓴다). 우리 에러 응답은 `description`까지 내려가서, 문구 하나만 달라도 가입 여부가 드러난다. 인증 메일 발송도 이미 가입 여부와 상관없이 같은 200을 준다(#9).
- **새 비밀번호가 규칙에 맞지 않으면 토큰이 폐기되지 않는다.** `@Valid` 검증(400)은 서비스보다 먼저 실행된다. 사용자는 비밀번호만 고쳐서 다시 보내면 된다.
- **구글로만 가입한 회원도 비밀번호가 생긴다.** 이메일 인증으로 본인 확인을 했으니 막지 않는다. 이후에는 이메일·비밀번호 로그인도 된다.
- 현재 비밀번호와 같은 비밀번호로 재설정하는 것은 막지 않는다. 비밀번호를 잊은 사람에게 "같은 비밀번호"라고 알려주는 것 자체가 정보가 된다.
- `revokeAll`의 벌크 DELETE는 `flushAutomatically = true`라서 새 비밀번호를 먼저 DB에 쓴 뒤 1차 캐시를 비운다(#22의 비밀번호 변경과 같은 방식).

## 변경 파일
- `AuthController`: `POST /password/reset` 추가
- `AuthService`: `resetPassword`, `getResetTarget` 추가
- `PasswordResetRequest`(새 파일): 이메일은 인증 때와 같은 기준(trim + 소문자)으로 맞춘다. 기준이 다르면 인증 때 저장한 Redis 키를 찾지 못한다
- `VerificationTokenService`: 401 예외를 `notVerified()`로 꺼내서 재설정과 같이 쓴다
- `PasswordRule`: `public`으로 바꿔 auth 패키지의 요청에서도 같은 규칙을 쓴다

## 테스트 (`PasswordResetApiTest`, 7개)
- 성공: 204, 새 비밀번호로만 로그인, 두 기기의 리프레시 토큰 삭제, 잠금 해제
- 같은 토큰 두 번 → 두 번째 401, 비밀번호는 첫 번째 값 유지
- 틀린 토큰 / 회원가입용 토큰 → 401, 비밀번호 그대로
- 가입하지 않은 이메일 → 토큰 오류와 본문(timestamp 제외)이 같은 401, 회원이 생기지 않음
- 구글 전용 계정 → 비밀번호가 생기고 이메일 로그인 가능, 구글 연결은 유지
- 규칙 위반 비밀번호 → 400, 같은 토큰으로 다시 보내면 204
- 대소문자·공백이 섞인 이메일 → 같은 회원으로 처리
