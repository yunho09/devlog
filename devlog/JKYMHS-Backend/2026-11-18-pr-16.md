### 1. 에러 코드와 상황별 메시지 (`global/exception`)
- `ErrorCode`: 이후 도메인이 던질 에러 25개를 상태코드별로 미리 정의했다 (`INVALID_CURSOR`, `SCHEDULE_LIMIT_EXCEEDED`, `CALENDAR_NOT_LINKED`, `PLAN_EXCEEDS_TRIP_PERIOD`(422), `AI_DAILY_LIMIT_EXCEEDED`(429), `EXTERNAL_API_ERROR`(502), `AI_SERVICE_UNAVAILABLE`(503) 등). 문구는 노션 API 명세서 문구다.
  - 422는 `HttpStatus.UNPROCESSABLE_CONTENT`를 쓴다. Spring 7에서 `UNPROCESSABLE_ENTITY`가 deprecated 되었기 때문이다 (값은 둘 다 422).
- `CustomException(ErrorCode, String message, String description)` 생성자 추가. 같은 code라도 상황마다 다른 문구를 보여줘야 할 때 쓴다.
  - 예: `SCHEDULE_LIMIT_EXCEEDED`의 기본 문구는 "일정에는 장소를 최대 30개까지…"지만 하루 한도 초과는 "하루에는 장소를 최대 10개까지…"로 보낸다. FE는 `code`로 분기하고 `message`는 그대로 띄우므로, 문구 때문에 에러 코드를 늘릴 필요가 없다.
  - 기존 두 생성자는 이 생성자를 부르도록 바꿨을 뿐 동작은 같다 (`getMessage()` = ErrorCode 기본 문구).
- `GlobalExceptionHandler.handleCustomException`이 `e.getMessage()`를 응답 message로 쓴다. 이 줄은 #8/#13에도 똑같이 있는 줄이라 합칠 때 충돌이 나지 않는다.
- `GlobalExceptionHandler.handleValidationException`: `@ModelAttribute` 쿼리 파라미터의 **타입 변환 실패**(`?companion=dog`, `?size=abc`)는 FieldError 기본 문구가 `Failed to convert property value…` 같은 스프링 영어 문구라서, `@RequestParam` 타입 오류와 같은 형식으로 바꿨다 (message `입력값이 올바르지 않습니다.`, description `companion: 요청 형식이 올바르지 않습니다.`). `@NotNull` 같은 검증 실패 문구는 그대로다. 이후 목록 API는 쿼리 파라미터를 `@ModelAttribute @Valid XxxRequest` record로 받기로 해서 필요했다.

### 2. FE 코드 값 enum (`global/web`, `global/model`, `global/config/WebMvcConfig`)
- FE는 `tab=festival`, `companion=kids`처럼 소문자 값을 쓰고, DB에는 대문자 `name()`을 저장한다. 그 사이를 이어주는 인터페이스가 `CodeEnum { @JsonValue String code(); }`다.
  - JSON 응답·요청 본문: `@JsonValue` 덕분에 Jackson이 `code()`로 쓰고 읽는다. 없는 값이 JSON으로 오면 `HttpMessageNotReadableException` → 기존 핸들러가 400.
  - 쿼리 파라미터: `CodeEnumConverterFactory`가 `code()`와 정확히 같은 값 → `name()`과 대소문자 무시로 같은 값 순으로 찾는다. 없으면 400.
  - 왜 `ConverterFactory<String, CodeEnum>`인가: 스프링은 변환기를 "enum 자기 자신 → 구현한 인터페이스 → `Enum`" 순으로 찾는다. 그래서 `CodeEnum`을 구현한 enum에만 이 변환기가 쓰이고, 나머지 enum은 스프링 기본 변환기가 그대로 처리한다.
  - DB 쪽은 엔티티의 `@Enumerated(STRING)`이 `name()`을 저장하므로, FE 값을 바꿔도 DB 데이터는 바뀌지 않는다.
- `Companion`(alone/couple/friends/kids/parents, `slowWalker()`는 kids·parents일 때 true)과 `ChildAgeGroup`(INFANT/ELEMENTARY/TEEN, code = name)은 회원 취향·찜·여행·AI 추천이 같이 쓰므로 `global/model`에 두었다.

### 3. 커서 기반 목록 (`global/pagination`)
- `CursorCodec`: 마지막 항목의 정렬 값을 JSON 객체로 만들어 base64url(패딩 없음)로 인코딩한다. FE에는 "불투명한 문자열"로만 약속해서, 담는 값을 나중에 바꿔도 FE는 그대로다.
  - 페이지 번호 대신 커서를 쓰는 이유: 목록을 넘기는 사이 항목이 추가·삭제돼도 중복·누락이 없고, `OFFSET`이 커질수록 느려지는 문제 없이 `WHERE (정렬값, id) > (커서값)`으로 인덱스를 탄다.
  - 비어 있음 / base64url 아님 / JSON 객체 아님 / 1024자 초과 → 400 `INVALID_CURSOR`.
  - JSON 숫자는 크기에 따라 `Integer`/`Long`으로 풀리므로 `requireLong`/`requireDouble`/`requireString`으로 꺼낸다. 사용자가 커서를 조작해 타입이 틀려도 `ClassCastException`(500) 대신 400이 난다.
  - `requireSame(cursor, key, expected)`: 다른 정렬·필터에서 만든 커서를 막는다. 커서를 만들 때 정렬·필터 값을 같이 넣고 풀 때 비교한다.
- `CursorPage<T>(items, nextCursor, hasNext)`: `CursorPage.of(size+1개 조회 결과, size, 커서 생성 함수)`. 다음 페이지 여부를 COUNT 쿼리 없이 size+1개 조회로 판단한다. `map()`으로 엔티티 → DTO 변환 시 커서는 유지한다.

### 4. 시계·스케줄링·비동기 (`global/config`)
- `ClockConfig`: `Clock.system(Asia/Seoul)` 빈. 이후 코드는 `LocalDate.now()` 대신 `LocalDate.now(clock)`를 쓴다. 서버 시간대가 UTC여도 축제 진행 상태·D-day가 한국 날짜로 계산되고, 테스트에서 시각을 고정할 수 있다.
- `SchedulingConfig`: `@EnableScheduling` + `@ConditionalOnProperty(batch.enabled, 기본 true)`. 테스트는 꺼두고 배치 메서드를 직접 부른다.
- `AsyncConfig` + `AsyncProperties(async.enabled, 기본 true)` + `ExecutorFactory.create(name, core, max, queue)`: 도메인마다 자기 실행기를 `@Bean`으로 만든다. 하나를 같이 쓰면 오래 걸리는 AI 추천이 행동 데이터 기록 같은 짧은 작업까지 막기 때문이다.
  - `async.enabled=false`(테스트)이면 `SyncTaskExecutor`를 돌려줘서 비동기 작업이 호출한 스레드에서 바로 끝난다. 테스트가 sleep으로 기다리지 않아도 된다.
  - 반환값은 반드시 `@Bean` 메서드로 등록한다. 스레드 풀 초기화·종료를 스프링이 맡는다 (팩토리 안에서 `initialize()`하면 스프링이 한 번 더 초기화해서 풀이 두 개 생긴다).

### 5. 도메인 간 이벤트 (`global/event`)
- 다른 도메인의 Repository를 직접 부르지 않고 이벤트로 알리기 위한 record 3개.
  - `UserWithdrawnEvent(userId)`: 탈퇴 직전 회원 도메인이 발행 → 찜·여행·추천·캘린더가 같은 트랜잭션(동기 `@EventListener`)에서 자기 데이터를 지운다. 회원 행을 지우기 전이라 FK 자식 행을 먼저 정리할 수 있다.
  - `BehaviorConsentRevokedEvent(userId)`: 행동 데이터 동의를 끄면 같은 트랜잭션에서 바로 삭제. 동의 변경이 롤백되면 삭제도 같이 롤백된다.
  - `BehaviorSignalEvent(userId, contentId, type, companion, tripId, occurredAt)` + `BehaviorSignalType`(가중치 VIEW 1, WISH 3, SCHEDULE_SAVE 5, CALENDAR 5, VISIT_SATISFIED 10, VISIT_NEUTRAL 5, VISIT_UNSATISFIED -3, AI_REMOVE -3): 취향 프로필 재료. 동의 여부는 받는 쪽이 확인한다.
