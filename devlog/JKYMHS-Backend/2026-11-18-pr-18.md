### 1. `tools/tourapi` 수집기 (`collect.py`, `indoor_outdoor.csv`)

### 2. 엔티티 (`domain/region`, `domain/category`, `domain/content/entity`)
- **`regions`**: 법정동 코드(`ldong_regn_cd`/`ldong_signgu_cd`) 기준 시·도(depth 1)·시·군·구(depth 2). 옛 관광공사 지역코드 대신 법정동 코드를 쓰는 이유는 KorService2 목록 응답이 법정동 코드를 주고, 2026년 행정구역 개편(전남광주통합특별시 등)도 여기에 먼저 반영되기 때문이다.
  - 시·도 행의 `ldong_signgu_cd`는 NULL이 아니라 `''`다. MySQL UNIQUE는 NULL끼리 중복으로 보지 않아서, NULL로 두면 같은 시·도가 두 번 들어갈 수 있다.
  - `short_name`은 화면 이름("서울특별시" → "서울")이다. 모든 API의 지역 이름은 이 값이고, `RegionNames`에 개편 전·후 이름을 둘 다 넣었다. 처음 보는 이름은 접미사("특별자치시" 등)를 떼서 쓴다.
- **`tour_classifications`**: 신 분류체계(lclsSystm) 대·중·소. 코드 자체가 PK다(관광공사가 정한 값이라 안 바뀌고, 콘텐츠도 코드 문자열로 들고 있다). 소분류만 `io_type`이 있다.
- **`categories` / `category_mappings`**: 분류 250개는 화면 필터와 맞지 않아서 화면용 묶음(장소 필터 6, 축제 필터 3, 홈 칩 4)을 따로 두고 분류 코드와 잇는다. 매핑 코드는 어느 단계든 된다(`HS`는 대분류 전체, `VE07`은 중분류). 콘텐츠의 lcls1/2/3 중 하나라도 같으면 그 카테고리다.
- **`contents`**: PK = TourAPI `contentid`. 운영 시간(`open_time`/`close_time`/`last_entry_time`), 쉬는 요일(`rest_days`: `MON,TUE` / `NONE`=연중무휴 / NULL=모름), 축제 기간·공연 시간, 실내외, 반려동물(`pet_allowed` NULL=모름), 인기 점수·찜 수, 소프트 삭제(`is_deleted`).
  - 지역·카테고리 id는 그냥 `Long` 컬럼으로 읽고, `@ManyToOne(insertable=false, updatable=false)`는 FK 제약을 만들려고만 둔다. 쓰기는 전부 JDBC라 JPA 연관관계로 쓸 일이 없다.
  - 인덱스 6개는 탐색 조회 순서(`content_type, is_deleted` 먼저)에 맞췄다. 인기순·이름순은 `(정렬값, id)` 커서로 인덱스만 읽고, 지도 bbox는 `(content_type, latitude, longitude)`를 탄다.
  - 원문(`operating_hours_raw`, `rest_date_raw`, `playtime_raw`)도 남긴다. 파서가 못 읽는 문장이 많아서 상세 화면은 원문을 보여준다.
- **`content_details`**(1:1, `@MapsId`) / **`content_images`**: 목록 조회가 수 KB짜리 소개글을 읽지 않게 따로 뒀다.
- **`batch_job_logs`**: 배치가 언제 돌았고 몇 건을 처리했는지, TourAPI를 몇 번 불렀는지. 인기 점수(D3)·방문 확인 메일(D4)도 같은 테이블을 쓰도록 `job_name`을 미리 정했다.
- **`tour_sync_cursors`**: 동기화 기준일(`MODIFIED_SINCE`)과 마지막으로 운영 정보를 받은 id(`INTRO_LAST_ID`). 서버가 재시작돼도 이어가려고 Redis가 아니라 DB에 둔다.

### 3. 서비스 계약 (다른 도메인은 테이블 대신 이것만 쓴다)
- `RegionService`: `getRegion`(없으면 400 "잘못된 필터 값입니다."), `getRegions`, `childrenOf`, `validateDistricts`(다른 시·도의 시·군·구면 400), `codeIndex()`(법정동 코드 → id 변환표). `RegionRef.fullName`은 "서울 중구" 형식이다.
- `CategoryService`: `getFilterCategories(tab)`, `getCategory(id)`, `lclsCodesOf(code)`(칩·카테고리 코드 → 분류 코드 집합, D1 칩 필터용), `matcher()`(적재용).
- `ContentService`: `getActiveSnapshot`(없거나 삭제 → 404 "존재하지 않거나 삭제된 장소입니다."), `findSnapshots`(삭제된 것도 `deleted=true`로 포함 — 찜·일정이 "삭제된 장소"를 보여줘야 해서), `findCandidatePool`(AI 후보: 관광지 + 기간이 겹치는 축제, 시·도 id면 그 시·도 전체, 인기순), `updatePopularityScores`(한 트랜잭션에서 전부 0 → 맵 값 1000건씩), `adjustWishCount`(`GREATEST(wish_count + ?, 0)` 한 줄 UPDATE라 동시 찜에도 수가 안 사라진다), `applyDetail`(D1 상세 갱신 결과 저장).
  - 넘기는 값은 엔티티가 아니라 `ContentSnapshot` record다. 다른 도메인이 지연 로딩이나 테이블 구조에 묶이지 않게 했다.
  - **쓰기는 JdbcTemplate `INSERT … ON DUPLICATE KEY UPDATE`를 1000건씩 batchUpdate로 보낸다.** CSV 3만 건을 JPA `save()`로 넣으면 건마다 SELECT + INSERT가 나가서 수 분이 걸린다. upsert는 인기 점수·찜 수·운영 정보·생성 시각은 건드리지 않고, 다시 받은 콘텐츠의 삭제 표시는 푼다. 축제 기간은 새 값이 없으면 기존 값을 둔다(`COALESCE`).
  - MySQL 8.0.19+의 `VALUES (…) AS new` 별칭을 쓴다. `COALESCE(new.col, col)`처럼 함수 안에서 기존 값을 부르면 "ambiguous" 오류가 나서 `contents.col`로 테이블 이름을 붙였다(테스트에서 실제로 걸렸다).
  - 컬럼 길이를 넘는 값은 잘라서 넣는다. 한 건 때문에 1000건 묶음 전체가 실패하지 않게 하기 위해서다.
- 계산 도우미 (DB에 저장하지 않는다 — 시각·날짜에 따라 계속 바뀌는 값이라 저장하면 매일 바꾸는 배치가 필요하다):
  - `OperatingHoursParser`: 처음 나오는 `HH:mm~HH:mm`(물결표 여러 종류·`-` 허용), `입장마감/매표마감 HH:mm`. `24:00`은 23:59로, 밤을 넘기는 영업은 close < open 그대로 둔다.
  - `RestDayParser`: `매주 X요일`·`X요일` → 그 요일들, `연중무휴`/`없음` → 빈 집합, `첫째`·`격주`처럼 매주가 아니면 null. 빈 집합(항상 연다)과 null(모름)을 섞지 않아서 "오늘 쉬는 곳 숨기기"가 모르는 곳까지 숨기지 않는다.
  - `OpenStatusCalculator`: 쉬는 요일 → `closed`, 시각 모름 → null, `[close−60분, close)` → `soon`, `[open, close−60분)` → `open`, 그 밖 → `closed`. 밤샘 영업은 close에 24시간을 더해 비교한다.
  - `FestivalStatus`: 시작 전 UPCOMING, 시작일~종료일(당일 포함) ONGOING, 그 뒤 ENDED.
- `ContentRedisKeys`: `popularity:version`, `candidates:*`, `tourapi:calls:{yyyyMMdd}`(TTL 2일), `lock:detail:{id}`(10초).
- `BatchJobLogService.start/finish`는 `REQUIRES_NEW`다. 배치가 자기 트랜잭션 안에서 실패해 롤백돼도 "실패했다"는 기록은 남아야 하기 때문이다.

### 4. TourAPI 클라이언트 (`domain/content/client`)
- KorService2 9개 오퍼레이션(`ldongCode2`, `lclsSystmCode2`, `areaBasedSyncList2`, `areaBasedList2`, `searchFestival2`, `detailCommon2`, `detailIntro2`, `detailImage2`, `detailPetTour2`).
- **일일 호출 수**: 시도할 때마다 Redis `tourapi:calls:{오늘}`을 INCR하고, `tour-api.daily-call-limit`(기본 1000)에 닿으면 실제로 부르지 않고 `TourApiQuotaExceededException`을 던진다. Redis에 세는 이유는 서버가 여러 대여도 같은 수를 보게 하려는 것이다. Redis가 안 되면 세지 않고 부른다(보조 장치라서. 진짜 한도는 포털이 알려준다).
- **한도 초과 응답**: 공공데이터포털은 `_type=json`이어도 키 오류·한도 초과를 XML로 준다. XML 본문, `LIMITED_NUMBER_OF_SERVICE_REQUESTS`, resultCode 22, HTTP 429는 한도 초과로 본다.
- **재시도**: 5xx·네트워크 오류(타임아웃 포함)만 3번까지, n번째 재시도 전 n × `retry-backoff`(1초) 대기. 4xx는 다시 불러도 같아서 바로 실패한다. 테스트는 `retry-backoff: 0ms`라 실제로 기다리지 않는다.
- **서비스 키 인코딩**: Decoding 키를 받아 URI를 만들 때 한 번만 인코딩한다(`+` → `%2B`). `UriComponentsBuilder.encode()` 뒤에 값을 채우면 값 안의 예약 문자까지 모두 인코딩된다. Encoding 키를 넣으면 두 번 인코딩돼서 `SERVICE_KEY_IS_NOT_REGISTERED`가 난다.
- 응답 항목은 `Map<String, String>`으로 읽는다(오퍼레이션마다 필드가 다르고 숫자도 문자열로 온다). 결과 없음은 `items: ""`, 한 건은 `item`이 배열이 아니라 객체로 오는 경우까지 처리했다.
- `RestClient.Builder`를 생성자로 받는 구조는 #8의 `GoogleOAuthClient`와 같다. 테스트가 `MockRestServiceServer`를 붙인 Builder를 넣는다. 실제 빈은 `TourApiConfig`가 타임아웃(10초)을 걸어서 만든다.

### 5. CSV 초기 적재 (`TourCsvImporter`, `ApplicationRunner` `@Order(2)`)
- `TOUR_IMPORT_CSV_DIR`이 있을 때만 서버 시작 시 돈다. 전체 데이터를 API로 받으면 수천 번 호출이 필요해서 하루 한도로는 며칠이 걸린다. 그래서 수집기로 받아둔 CSV를 넣고 이후엔 변경분만 받는다.
- 순서: 지역 → 분류(+ 실내외 표) → 카테고리 시드 → 콘텐츠(이때 지역 id·카테고리·실내외를 정한다) → 운영 정보(운영 시간·쉬는 날·축제 시간 컬럼). 3만 건마다 DB를 조회하지 않도록 변환표(`ContentLoadContext`)를 한 번 읽어둔다.
- 좌표가 없거나 기간이 없는 축제는 넣지 않는다(기능 명세서 006-01). 시·군·구 코드를 모르면(지역 목록에 없는 코드, 세종) `region_id`를 시·도 id로 채워서 시·도 필터에서는 빠지지 않게 했다.
- 전부 upsert라 몇 번 돌려도 결과가 같다(지역 id도 유지된다). 끝나면 `MODIFIED_SINCE`를 CSV의 가장 최근 수정일로 맞추고 `TOUR_IMPORT` 로그를 남긴다.
- UTF-8 BOM(`utf-8-sig`)을 직접 건너뛴다(commons-io 없이). 남아 있으면 첫 헤더가 `﻿content_id`가 돼서 칸을 못 찾는다.
- 실패해도 서버 시작은 막지 않는다(FAILED 기록 + 알림). 탐색은 빈 결과로라도 뜨는 편이 낫다고 봤다.
- `CategorySeeder`(`@Order(1)`, 항상 실행)는 코드 기준으로 카테고리·매핑을 시드와 똑같이 맞춘다. 테스트는 매번 테이블을 비우므로 필요한 테스트가 `seed()`를 직접 부른다.

### 6. 04:00 동기화 배치 (`TourSyncJob`, `@Scheduled(cron = "${tour-api.sync.cron}", zone = "Asia/Seoul")`)
1. 변경분: 종류(12·14·15·32·39)마다 `areaBasedSyncList2(modifiedtime=기준일)`를 1000건씩 받아 upsert, `showflag=0`은 삭제 표시. 동기화 목록엔 축제 기간이 없어서 먼저 `searchFestival2`로 같은 기간에 바뀐 축제의 기간을 받아 붙이고, 이미 저장된 축제는 저장된 기간을 쓴다. 기간을 끝내 모르는 새 축제·좌표 없는 항목은 건너뛴다.
2. 운영 정보: 안 받았거나 30일 지난 관광지·축제를 오래된 순으로 `intro-per-run`(300)건 `detailIntro2`. 3만 건을 하루 한도 안에서 나눠 받기 위한 것이다.
3. 변경분을 끝까지 받았을 때만 기준일을 오늘로 옮긴다. 한도 초과로 중간에 멈추면 **PARTIAL + 기준일 유지** → 다음 실행이 같은 날짜부터 다시 받는다(upsert라 다시 받아도 결과가 같다).
4. 콘텐츠가 바뀌었으니 AI 추천 후보 캐시 `candidates:*`를 지운다. `KEYS`는 Redis를 멈추게 해서 `SCAN`으로 찾는다.
5. 예외 → `FAILED` 기록 + `BATCH_ALERT_WEBHOOK_URL`로 `{"text": …}` POST(없으면 ERROR 로그). 서비스 키가 없거나 콘텐츠·기준일이 둘 다 없으면(CSV 적재 전) 경고만 남기고 아무것도 안 한다. 전체 적재는 API로 하지 않는다.
- 스케줄 on/off는 #16의 `SchedulingConfig`(`batch.enabled`)가 정한다. 테스트는 꺼두고 `run()`을 직접 부른다.

### 7. API (`GET /api/regions`, `GET /api/categories`)
- 지역 목록은 시·도 → 시·군·구 2단계에 축제·관광지 개수를 붙인다. 개수는 삭제 안 된 관광지 + 끝나지 않은(진행 중·예정) 축제이고, 시·도 값은 아래 시·군·구 합(+ 시·군·구가 없는 콘텐츠)이다. GROUP BY 한 번으로 세고 Java에서 합친다. `Cache-Control: max-age=86400`(하루에 한 번 정도만 바뀐다).
- 응답 조립을 `RegionService`가 아니라 `RegionListService`에 둔 이유: `ContentService`가 이미 `RegionService`를 쓰므로, `RegionService`가 다시 `ContentService`를 부르면 순환 의존이 된다.
- 카테고리 목록은 `tab=place|festival`(생략하면 둘 다, 장소 → 축제 순). 칩은 홈 고정 버튼이라 넣지 않는다. 모르는 tab은 #16의 `CodeEnumConverterFactory`가 변환에 실패해서 400이다.
- 이 브랜치(develop 계열)에는 `SecurityConfig`가 없어서 permitAll은 추가하지 않았다. D3에서 공개 경로를 한꺼번에 보장한다(계획 §3.2).

### 8. 설정

## 확인 필요

- 실내외 값은 CSV의 `io` 칸이 아니라 `seed/indoor_outdoor.csv`(소분류 기준)에서 정한다. 같은 표에서 나온 값이라 지금은 같지만, 표를 고치면 다시 적재해야 반영된다.
