# 2026-11-06

## 요약
승인자가 코드 없이 작업 내용을 직관적으로 이해할 수 있도록 AI 작업 설명(`TaskExplanation`) 기능을 추가했습니다. DB 스키마에 jsonb 컬럼을 추가하고 Bedrock 프롬프트 및 응답 DTO에 설명 구조를 반영했습니다. 또한 Bedrock 타임아웃 설정이 실제로 적용되도록 수정하고, 설명 파싱 실패 시에도 전체 분석이 실패하지 않도록 안정성을 보강했습니다.

## 변경 내용
- DB 마이그레이션(V10)을 통해 `tasks` 테이블에 `explanation` jsonb 컬럼 추가 및 `TaskExplanation` 클래스 신설
- `AiTask`, `Task`, `TaskResponse` 등 주요 모델 및 DTO에 `explanation` 필드 반영
- AI 프롬프트에 작업 설명 생성을 위한 스키마 및 근거 제공 규칙 추가
- AI 응답 파싱 시 설명 필드 추출에 실패할 경우 설명만 `null`로 처리하고 분석 자체는 성공하도록 폴백 로직 구현
- 기존에 미적용되던 Bedrock 타임아웃 설정(기본 120초)을 SDK 클라이언트에 명시적으로 연결 및 `max-tokens` 기본값(8192) 조정
- 롤백 및 에디터 작업 시 설명 필드는 `null`로 처리하고, 서명 해시 계산(`hashTarget`)에는 영향이 없음을 검증하는 테스트 추가

## 의도
코드에 대한 전문 지식이 없는 승인자가 AI가 제공하는 자연어 설명을 바탕으로 작업의 안전성과 타당성을 쉽게 검토할 수 있도록 하기 위함입니다. 아울러 AI 서비스 연동 시 발생할 수 있는 타임아웃 및 파싱 오류 상황에서 시스템 전체의 가용성이 떨어지지 않도록 보완하고자 했습니다.

## 트러블 슈팅
- Bedrock 타임아웃 설정이 실제 SDK 클라이언트에 주입되지 않고 기본 30초로 동작하던 문제 → `BedrockConfig`에서 타임아웃 설정(120초)을 명시적으로 연결하여 긴 요청에 대응할 수 있도록 해결
- AI 응답에서 설명 부분 파싱 실패 시 분석 전체가 실패 처리될 위험 → 파싱 예외 발생 시 설명 필드만 `null`로 비워두고 전체 분석 결과는 정상 반환하도록 예외 처리 구현

## 생각 정리
1. AI 생성 설명 파싱 실패 시 전체 요청을 실패 처리하지 않고 `explanation`만 `null`로 보전하는 방식이 시스템 가용성과 사용자 경험 측면에서 적절한 선택이었는가?
2. 무결성 검증을 위한 `hashTarget` 서명 계산 대상에서 `explanation` 필드를 제외하기로 한 판단이 보안 요구사항과 서비스 확장성 측면에서 올바른 기준인가?
3. 외부 AI 서비스(Bedrock) 연동 시 타임아웃 미주입 문제나 파싱 실패와 같은 불확실성을 다루면서 예외 처리 설계에 대해 무엇을 배웠는가?
