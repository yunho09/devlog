# 2026-11-25

## 요약
영수증 스캔 기능에서 LLM(Gemini)이 출력하는 이모지 중 도형이나 박스 형태의 특수 문자를 거르고 기본 재료 도감의 이모지와 동기화되도록 수정했습니다. 유니코드에 적절한 이모지가 없는 재료에서 흰 네모(U+2B1C) 등의 도형 문자가 저장되는 문제를 해결하고, 기본 도감에 동일한 이름의 재료가 존재하면 해당 도감의 이모지를 우선 적용했습니다. 또한 이전 PR(#70) 변경으로 인해 깨진 테스트 코드의 사용자 조회 방식을 보완했습니다.

## 변경 내용
- **도형 문자 파싱 필터링**: `ReceiptItemParser.toEmoji`에서 도형 및 상자 문자 영역(U+2500–25FF, U+2B00–2BFF, U+FFFD 및 변형 선택자)으로만 이루어진 값을 `null`로 변환하도록 수정.
- **도감 이모지 우선 적용 및 프롬프트 개선**: `ReceiptScanService`에서 Gemini 스캔 결과의 재료명이 기본 공용 도감 재료명과 일치하면 도감의 이모지로 대체하고, 프롬프트에 적절한 이모지가 없을 시 도형 문자 대신 `null`을 반환하도록 지침 추가.
- **테스트 케이스 고치기**: `IngredientCatalogImageControllerTest`에서 `users.login_id` 제거 이후 깨진 테스트의 사용자 조회 방식을 `u.loginId`에서 `u.email`로 변경.
- **검증 테스트 추가**: `ReceiptItemParserTest` 및 `ReceiptScanControllerTest`에 도형 필터링 및 도감 이모지 대체 로직 테스트 구현.

## 의도
영수증 스캔 검증 중 '두부' 항목의 아이콘이 흰 네모(U+2B1C)로 표기되는 현상이 발견되었습니다. 유니코드상 두부 이모지가 없어 LLM이 대체 도형 문자를 생성했고, 기존 서버 검증 로직이 이를 걸러내지 못했기 때문입니다. 도형 문자를 무효화하여 프론트엔드가 아이콘 없이 안전하게 처리할 수 있게 하고, 기본 도감 재료와 일치할 경우 일관된 이모지를 제공하도록 보완했습니다.

## 트러블 슈팅
- 영수증 스캔 시 특정 재료(예: 두부)에 유니코드 이모지가 없어 LLM이 흰 네모(U+2B1C) 같은 도형 문자를 반환하여 클라이언트에 출력되는 문제 → `ReceiptItemParser`에 유니코드 도형 범위(U+2500–25FF, U+2B00–2BFF 등) 감지 시 `null`을 반환하는 정규화 로직을 추가하고, 공용 도감 재료명과 일치할 경우 도감 이모지를 덮어씌우도록 수정.
- 선행 PR(#70)의 DB schema 변경(`login_id` 제거) 후 develop 브랜치 테스트 실행시 `IngredientCatalogImageControllerTest`가 실패하는 문제 → 사용자 검색 로직을 `u.loginId`에서 `u.email`로 고친 별도 커밋(`5dd3ea2`)을 추가하여 해결.
