## 요약
레시피 접근 권한 확인 로직과 입력값 검증용 정규식을 공통 모듈로 추출하여 중복 코드를 정리한 리팩토링 PR입니다. `RecipeFinder`를 신설하여 `RecipeService`와 `MissingIngredientService`에서 중복되던 레시피 조회 및 권한 검증 로직을 일원화하고 불필요한 의존성을 제거했습니다. 또한 여러 DTO에 산재해 있던 제어 문자 방지 정규식을 `TextPatterns` 상수로 통합하고 코드 스타일을 정리했습니다.

## 변경 내용
- `RecipeFinder` 클래스를 신설하여 레시피 존재 여부 확인 및 냉장고 멤버 접근 권한 검증 로직(`findAccessible`)을 공통화
- `RecipeService` 및 `MissingIngredientService`에 `RecipeFinder`를 적용하고, `MissingIngredientService` 내 불필요한 `RecipeRepository`, `FridgeAccessValidator` 의존성 제거
- 줄바꿈 및 제어 문자를 막는 정규식을 `global/util/TextPatterns` 상수로 분리하고 `FridgeItemUpdateRequest`, `TargetRecipeRequest`, `ShoppingListItemCreateRequest`에 적용
- `RecipeCandidate`, `RecipeCandidateParser`에서 쓰지 않는 `IngredientSource` import 제거 및 `RecipeCandidateSelector` 빈 줄 정리
- 작업 범위 초과로 포함되었던 `CookingService` 및 `RecipeIngredientRepository` 수정 사항을 되돌림(Revert)

## 의도
동일한 검증 로직과 정규식 코드가 여러 파일에 복사·붙여넣기되어 있던 구조를 개선하여 코드 재사용성과 유지보수성을 높이기 위해 수행되었습니다. API 응답 및 오류 코드, 기존 동작 방식을 그대로 유지하면서 담당 코드 범위 내의 중복을 정리하고자 했습니다.
