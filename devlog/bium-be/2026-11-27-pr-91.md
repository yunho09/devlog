# 2026-11-27

## 요약
영수증 스캔 서비스에서 요청의 Content-Type 헤더만으로 파일 형식을 판단하던 문제를 해결하기 위해 파일 매직 바이트(Signature) 검증 로직을 추가했습니다. 이미지 파일이 아닌 파일에 이미지 Content-Type만 지정해 전달할 경우 Gemini AI API가 호출되어 사용 한도가 차감되거나 502 에러가 발생하는 현상을 방지합니다. 파일 앞부분 바이트를 확인하여 허용된 5가지 사진 형식(JPEG, PNG, WEBP, HEIC, HEIF)이 아닌 경우 AI 및 제한기 호출 전 400 에러로 즉시 거절합니다.

## 변경 내용
- `ReceiptScanService`에 파일 헤더 시그니처(Magic Byte) 기반 이미지 포맷 검증 로직 추가.
  - JPEG (`FF D8 FF`), PNG (`89 50 4E 47 0D 0A 1A 0A`), WEBP (`RIFF....WEBP`) 매직 바이트 검사.
  - HEIC/HEIF: `ftyp` 상자의 대표 브랜드 및 호환 브랜드 내 `heic` 계열/`mif1`·`msf1` 검사 (AVIF 등 타 포맷은 차단).
- 검증 실패 시 Gemini API 및 호스트 사용 제한기(Rate Limiter) 호출 전에 400 `INVALID_RECEIPT_IMAGE` 예외 반환.
- `ReceiptScanControllerTest`에 파일 시그니처 검증 테스트 케이스(비이미지, AVIF, 정상 포맷들) 추가.
- 기존 테스트용 mock 바이트 데이터(`{1, 2, 3}`)를 유효한 JPEG 매직 바이트로 수정.

## 의도
클라이언트가 전달하는 `Content-Type` 헤더는 위변조가 가능하므로, 실제 파일 바이너리의 앞부분(Magic Byte)을 검증하여 허위 요청을 선제 차단하기 위함입니다. 이를 통해 불필요한 Gemini AI API 호출로 인한 비용/한도 소모와 502 에러 발생을 예방합니다.

## 트러블 슈팅
- 문제: 클라이언트의 Content-Type 헤더만 신뢰하여 텍스트/HTML 등 비이미지 파일이 전송될 경우, Gemini AI API까지 요청이 전달되어 AI 한도가 소모되고 502 에러가 발생함 → 해결: Gemini API 및 Rate Limiter를 부르기 전, 파일의 바이트 시그니처를 검사하여 지원하지 않는 포맷은 400 `INVALID_RECEIPT_IMAGE`로 즉시 거절하도록 얼리 리턴 로직 구현.
- 문제: 매직 바이트 검증 기능 도입 후 기존 컨트롤러 단위 테스트에서 사용하던 가짜 이미지 바이트 데이터(`{1, 2, 3}`)로 인해 테스트가 실패함 → 해결: 테스트 데이터의 바이트 배열을 실제 JPEG 매직 바이트로 수정하여 테스트 통과.
