## 요약
알림 설정을 명시적으로 저장하지 않은 사용자에게 알림 메일이 발송되지 않던 문제를 해결했습니다. 회원가입 시 기본 알림 설정 레코드를 함께 생성하도록 수정하고, 기존 사용자를 위한 스타트업 마이그레이션 로직을 추가했습니다.

## 변경 내용
- `AuthService.signup`에서 기본 냉장고 생성 후 동일 트랜잭션 내에서 `NotificationSettingService.createDefault`를 호출하도록 변경
- 알림 설정 레코드가 없는 기존 사용자를 위해 서버 기동 시 1회 실행되는 `DefaultNotificationSettingMigration` 구현 (`insert ... select ... where not exists` 활용)
- `NotificationSettingService` 내 `DEFAULT_NOTIFY_TIME` 상수의 접근 제어자를 `public`으로 변경 및 ERD 문서 업데이트
- 회원가입 직후 알림 설정 미저장 사용자의 알림 발송 검증 및 마이그레이션 멱등성 검증 테스트 작성

## 의도
화면상에는 알림 설정 기본값(켜짐)이 보여도 실제 DB 레코드가 없어 예약 작업 대상(`findDue`)에서 누락되던 문제를 바로잡기 위함입니다. 신규 가입자 및 기존 미저장 사용자 모두 기본값대로 알림 메일을 정상 수신할 수 있도록 보장하고자 했습니다.

## 트러블 슈팅
- 알림 설정을 별도로 변경하지 않은 사용자의 경우 DB 레코드가 없어 알림 대상 쿼리(`findDue`)에서 누락됨 (화면 저장 버튼은 변동 사항이 없어 비활성화되어 기본값 저장 불가) → 회원가입 시 기본 설정 레코드를 자동 생성하고, 기존 사용자는 `DefaultNotificationSettingMigration`을 통해 멱등성 있는 SQL 실행으로 기본 레코드를 일괄 생성하도록 해결.
