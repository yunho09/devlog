## 요약
로그인한 사용자의 냉장고 재료를 기반으로 레시피를 추천하고, 추천 결과를 저장하여 상세 조회할 수 있는 API를 구현했습니다. Gemini API 호출 시 대기 시간 동안 DB 커넥션이 고갈되지 않도록 저장 시점에만 트랜잭션을 적용하도록 구조를 개선했습니다. 또한 냉장고 접근 권한 검증과 사용자 단위의 호출 제한(Rate Limit)을 적용해 보안 및 안정성을 강화했습니다.

## 변경 내용
- 레시피 추천 요청 시 사용자 전달 재료 대신 냉장고(`fridge_items`) 내 유효 재료(유통기한 미경과, 미삭제)를 자동 조회하도록 변경
- 추천 결과 저장 및 레시피 상세 조회 API(`GET /api/recipes/{recipeId}`) 구현
- 외부 AI(Gemini) 대기 시간 중 DB 커넥션 점유 방지를 위해 `TransactionTemplate` 기반 저장 시점 트랜잭션 적용
- `FridgeAccessValidator`를 추가하여 냉장고 멤버가 아닌 경우 403 대신 404를 반환해 냉장고 존재 여부 은닉
- 레이트 리밋 정책 변경 (IP 기준 → 사용자 ID 기준 분당 5회, 유효 재료가 없는 422 응답 시 차감 제외)
- 프롬프트 전달 전 재료명 내 제어 문자 및 줄바꿈 공백 처리
- `Recipe`, `FridgeItem`, `RecipeIngredient` 엔티티 필드 추가(`emoji`, `tips`, `difficulty`, 영양 정보 등) 및 ERD 반영

## 의도
프론트엔드가 재료를 직접 넘기는 방식 대신 로그인한 사용자의 실제 냉장고 데이터를 연동하여 서비스의 일관성과 사용자 경험을 개선하기 위함입니다. AI 응답 지연으로 인한 DB 커넥션 풀 고갈을 방지하고, 타인의 냉장고 정보 유출을 막는 보안 로직을 강화하기 위해 변경을 진행했습니다.
