## API 변경 (FE와 맞춤: bium-fe#57)
- `GET /api/ingredient-catalogs`
  - 내 재료(최근 순서) 다음에 기본 재료(넣은 순서)를 줍니다. 즐겨찾기한 재료가 맨 위에 오는 규칙은 그대로입니다.
  - 응답의 각 재료에 `basic`(boolean)이 생겼습니다. 기본 재료면 true입니다.
  - 기본 재료를 넣기 전에 같은 이름을 직접 추가한 사용자도 있을 수 있어서, 내 재료와 이름이 같은 기본 재료는 빼고 줍니다.
- `POST /api/ingredient-catalogs`: 기본 재료와 이름이 같으면 `DUPLICATE_CATALOG_NAME`(409)입니다. 도감에 같은 재료가 두 개 보이지 않게 하려는 것입니다.
- 기본 재료로 할 수 있는 것과 없는 것
  - 할 수 있음: `POST /api/fridges/{fridgeId}/items`(냉장고에 넣기), `POST /api/fridges/{fridgeId}/purchased-items`(장본 음식 담기), 즐겨찾기 추가·해제
  - 할 수 없음: `DELETE /api/ingredient-catalogs/{catalogId}`. 기본 재료는 지울 수 없어서 `CATALOG_NOT_FOUND`(404)가 옵니다.
  - 다른 사용자의 재료는 지금처럼 쓸 수 없습니다(404).
- `findByIdAndOwnerId`를 쓰던 냉장고에 넣기·장본 음식 담기·즐겨찾기를 `findUsableById`(내 재료 또는 공용 도감)로 바꿨습니다. 삭제는 그대로 내 재료만 찾습니다.
