냉장고 공유 화면의 활동 기록에 쓸 기록 남기기와 조회 API를 추가했습니다.
재료를 넣고·고치고·지우거나 멤버가 참여·나갈 때 누가 무엇을 했는지 `activity_logs`에 남기고, 냉장고 멤버가 최근 기록을 볼 수 있습니다.

## 변경 사항
- **활동 기록 조회** `GET /api/fridges/{fridgeId}/activities` (멤버만)
  - 최근 순으로 50개까지 `[{ id, nickname, action, itemName, createdAt }]`
  - 기록마다 닉네임을 꺼낼 때 쿼리가 따로 나가지 않게 사용자를 함께 불러옵니다
- **기록 남기기** (`ActivityLogService.recordItem`, `recordMember`)

  | 동작 | action | 사람 | itemName |
  |---|---|---|---|
  | 도감 재료를 냉장고에 넣기 | `ADD` | 넣은 사람 | 넣은 이름 |
  | 재료 수정 | `UPDATE` | 고친 사람 | 고친 뒤 이름 |
  | 재료 삭제 | `DELETE` | 지운 사람 | 지운 재료 이름 (지운 뒤에도 남음) |
  | 초대 코드로 참여 | `JOIN` | 참여한 사람 | null |
  | 냉장고 나가기 | `LEAVE` | 나간 사람 | null |
  | 멤버 내보내기 | `LEAVE` | 내보내진 사람 | null |

- 기록은 그 동작과 같은 트랜잭션에서 남겨서, 동작이 실패해 되돌려지면(버전 충돌 등) 기록도 남지 않습니다
- 바꾼 값 없이 저장만 누른 수정은 기록하지 않습니다
- 재료 삭제는 삭제를 먼저 저장한 뒤 기록을 남깁니다. 기록이 재료 행을 참조해서, 순서가 반대면 MySQL에서 같은 재료를 동시에 지울 때 서로 기다리다 막힙니다(데드락). 지금 순서에서는 늦은 요청이 409 `CONCURRENT_MODIFICATION`으로 끝납니다

## 확인 부탁드립니다
- **강희 님:** 재료 넣기(`FridgeItemService.create`)에 `ADD` 기록 한 줄을 추가했습니다.
- **선재 님:** 이동·차감·되돌리기(`MOVE`·`DEDUCT`·`RESTORE`)는 아직 남기지 않습니다. 같은 트랜잭션 안에서 `activityLogService.recordItem(userId, item, ActivityAction.DEDUCT)`처럼 한 줄 부르면 되는데, 차감은 재료 여러 개가 한 번에 바뀌어서 재료마다 남길지 요리 한 번에 하나로 남길지 같이 정하고 싶습니다.
- 내보내기는 `ActivityLog`에 사람이 한 명만 들어가서 **내보내진 사람의 `LEAVE`** 로 남깁니다. 누가 내보냈는지 보여 줘야 하면 `REMOVE` 같은 action을 따로 두면 됩니다.
- 명세는 FE 공유 화면(`feat/fridge-share-view`)과 맞췄습니다.
