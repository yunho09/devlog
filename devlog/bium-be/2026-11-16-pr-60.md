## 요약
컨트롤러마다 `@AuthenticationPrincipal Jwt jwt`를 전달받아 `Long.valueOf(jwt.getSubject())`로 사용자 ID를 파싱하던 방식을 커스텀 어노테이션 `@LoginUserId`로 리팩터링했습니다. 별도의 ArgumentResolver 등록 없이 Spring Security의 SpEL을 활용한 메타 어노테이션으로 구현했습니다. 담당 컨트롤러 7개에 우선 적용했으며, 파라미터 이름 충돌 건을 수정하고 전체 테스트를 통과했습니다.

## 변경 내용
- `@AuthenticationPrincipal(expression = "T(java.lang.Long).valueOf(subject)")`을 메타 어노테이션으로 가질 `@LoginUserId` 신규 생성
- 7개 컨트롤러(`ActivityLogController`, `FridgeInviteController`, `FridgeMemberController`, `RecipeController`, `NutritionController`, `ShoppingListItemController`, `MissingIngredientController`)의 사용자 ID 수신 방식을 `@LoginUserId Long userId`로 일괄 변경
- `FridgeMemberController.remove`에서 경로 변수 `{userId}`와의 파라미터 이름 충돌을 피하기 위해 `@PathVariable("userId") Long targetUserId`로 명시적 매핑 수정
