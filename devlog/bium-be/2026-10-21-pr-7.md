# 2026-10-21

## 요약
프론트엔드에서 직접 호출하던 Gemini API 기반 레시피 추천 로직을 백엔드 서버로 이전하고 추천 API(`POST /api/recipes/recommendations`)를 구현했습니다. API 키를 서버 환경변수로 일관되게 관리하며 IP 및 서버 전체 단위의 호출 사용량 제한(Rate Limiting)을 추가했습니다. 또한 외부 AI 연동 시 발생할 수 있는 예외 처리 체계를 정비하고 Spring Security 인증 구성을 개선했습니다.

## 변경 내용
- **Gemini 클라이언트 연동 (`global/gemini`)**: `x-goog-api-key` 헤더를 통한 API 키 관리, Gemini API 429 오류 시 503(`AI_QUOTA_EXCEEDED`), 기타 호출 실패 시 502 응답 매핑 logic 추가
- **레시피 추천 도메인 로직 (`domain/recipe/recommendation`)**: 유통기한 임박 재료 우선 프롬프트 작성, 응답 파싱, 미보유 필수 재료/디저트/음료 레시피 제외 및 유사 레시피 필터링 후 4개 레시피 추천 로직 구현
- **추천 API 및 사용량 제한**: `POST /api/recipes/recommendations` 엔드포인트 구현, IP당 분당 5회 및 서버 전체 분당 15회 제한(`RecommendationRateLimiter`), 초과 시 429 응답 및 `Retry-After` 헤더 반환
- **공통 및 보안 설정 개선**:
  - `ErrorCode`에 추천 관련 오류 코드 5종 추가 및 `BusinessException`에 원인 예외 전달 생성자 추가
  - `GlobalExceptionHandler`에 `TooManyRequestsException` 처리 추가
  - `SecurityConfig`: 추천 API 비인증 허용, 공개 API 요청 시 만료된 Bearer 토큰 무시를 위한 `bearerTokenResolver` 경로 추가, `/error` 포워딩 시 401 변환 방지를 위해 `DispatcherType.ERROR` 허용
  - `ClockConfig` 추가 (`Asia/Seoul` 기준 `Clock` 빈 등록)

## 의도
프론트엔드에 노출되어 있던 Gemini API 키를 백엔드 서버 환경변수로 이관해 보안성을 높이고, 레시피 추천 로직 및 트래픽 제한 제어 권한을 백엔드로 가져오기 위함입니다. 차후 냉장고 재료 DB 조회 및 추천 레시피 저장 기능과의 연동을 용이하게 하기 위한 기반 작업입니다.

## 트러블 슈팅
- **한 글자 재료 이름 동질성 비교 오류** → `IngredientMatcher`에서 한 글자로 된 재료 이름이 다른 재료 이름 검사 시 오탐되는 문제 해결 (`67f5d58` 커밋)
- **공개 API에 만료된 Bearer 토큰 동시 전달 시 401 발생** → `bearerTokenResolver`에 공개 API 경로를 등록하여 만료된 토큰이 넘어오더라도 검증 과정 없이 무시하도록 수정
- **오류 응답 포워딩 시 Security 401 반환** → DispatcherType.ERROR가 보완 필터에 걸려 `/error` 처리 중 401로 응답이 바뀌던 현상을 `SecurityConfig`에서 `DispatcherType.ERROR`를 permitAll하여 해결
