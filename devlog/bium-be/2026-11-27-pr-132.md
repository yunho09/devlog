- PR 제목: feat: 내가 추가한 도감 재료를 고치는 API 추가
- PR 본문: ## 변경
- `PUT /api/ingredient-catalogs/{catalogId}`: 본문은 도감 추가와 같은 `IngredientCatalogCreateRequest`(`name`, `emoji`, `category`, `shelfLifeDays`)를 그대로 써서 검증 규칙(이름 30자·제어 문자, 이모지 한 개, 유통기한 1~365일)도 같다. 고친 재료를 `IngredientCatalogResponse`로 돌려준다.
- 내가 추가한 재료만 고친다. 기본 재료와 남의 재료는 지울 때와 같이 `CATALOG_NOT_FOUND`(404).
- 이름을 바꿀 때 다른 내 재료나 기본 재료와 같으면 `DUPLICATE_CATALOG_NAME`(409). 동시에 같은 이름으로 바꾸면 `(owner_key, name)` 유니크 제약에서 같은 409로 바꾼다. 이름을 그대로 두고 다른 값만 고칠 수 있다.
- 사진 바꾸기(`changeImage`)와 같은 행을 잠가(`findUsableByIdForUpdate`) 차례로 바꾼다. 잠그지 않으면 한쪽이 읽어 둔 옛 사진 키로 다른 쪽이 바꾼 사진 키를 덮어쓸 수 있다.
- 이 재료로 넣은 냉장고 재료·장본 음식은 이름·아이콘을 따로 저장하므로 그대로 두고, `catalog_id` 연결도 그대로다.
- 사용자 재료에는 기본 보관 위치가 없어(추가할 때도 받지 않는다) 수정 항목에 넣지 않았다.
