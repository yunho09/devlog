# 2026-11-20

## 요약
냉장고 주인이 멤버를 강제로 내보낼 때 기존에는 스스로 나간 것(`LEAVE`)과 구분되지 않던 문제를 해결하기 위해 `REMOVE` 액션을 추가하고 내보낸 대상 사용자를 기록하도록 개선했습니다. `activity_logs` 테이블 및 관련 엔티티에 `target_user_id`를 추가하고 활동 기록 조회 응답 DTO에 `targetNickname` 필드를 반영했습니다. 또한, 기존 DB 환경에서 JPA `ddl-auto: update` 사용 시 enum CHECK 제약조건 업데이트가 누락되어 발생하는 500 에러를 방지하기 위해 마이그레이션 로직을 보완했습니다.

## 변경 내용
- `ActivityAction` enum에 `REMOVE` 항목 추가
- `activity_logs` 테이블 및 엔티티에 `target_user_id` (null 허용, users 참조) 추가 및 `docs/ERD.dbml`에 반영
- 멤버 내보내기 API(`DELETE /api/fridges/{fridgeId}/members/{userId}`) 처리 시 기존 `LEAVE` 기록 대신 내보낸 주인을 주체로, 대상 멤버를 대상으로 하는 `REMOVE` 기록 저장
- 활동 기록 조회 API(`GET /api/fridges/{fridgeId}/activities`) 응답 DTO(`ActivityLogResponse`)에 `targetNickname` 필드 추가 (`REMOVE`일 때만 값 존재)
- 기존 `IngredientSourceCheckMigration`을 여러 enum 필드의 CHECK 제약을 재설정하는 `EnumCheckConstraintMigration`으로 확장하고 `@Order(HIGHEST_PRECEDENCE)` 추가
- 변경된 활동 로그 및 마이그레이션 검증 테스트 작성 및 기존 테스트 수정

## 의도
냉장고 멤버 내보내기 수행 시 기존에는 스스로 나간 것과 동일하게 `LEAVE`로만 남아서 "누가 누구를 내보냈는지" 구분할 수 없었습니다. 내보내기 행위를 독립된 이벤트(`REMOVE`)로 분리하여 내보낸 사람과 내보내진 사람을 명확히 기록하고, 이를 프론트엔드 UI에서 보여줄 수 있도록 API 응답 구조를 개선하기 위해 작업했습니다.

## 트러블 슈팅
- 기존 DB에서 Hibernate `ddl-auto: update` 사용 시 enum CHECK 제약(`activity_logs_chk_1`)이 변경되지 않아 `REMOVE` 로그 저장 시 500 에러 발생 → 서버 시작 시 기존 enum CHECK 제약을 지우고 최신 enum 값 기준으로 재생성하도록 `EnumCheckConstraintMigration`으로 확장 구현하여 해결
- CHECK 제약 마이그레이션 작업이 외부 API 조회 등 다른 시동 작업보다 늦게 실행되어 발생할 수 있는 문제 → 마이그레이션 빈에 `@Order(HIGHEST_PRECEDENCE)`를 붙여 최우선 순위로 실행되도록 설정
