# 2026-11-28

## 요약
액세스 토큰 만료 후에도 로그인 상태를 안전하게 유지하기 위한 리프레시 토큰(Refresh Token) 메커니즘을 추가했습니다. 토큰 보안을 위해 DB에는 SHA-256 해시값만 저장하며, 토큰 재발급 시 일회성으로 소비하고 새로 발급하는 토큰 회전(Rotation) 방식을 적용했습니다. 동시 요청으로 인한 경쟁 상태를 방지하기 위한 행 잠금 처리와 함께 갱신 및 로그아웃 API를 구현했습니다.

## 변경 내용
- **로그인 응답 확장**: `LoginResponse` DTO에 `refreshToken` 필드를 추가했습니다.
- **리프레시 토큰 DB 저장소 구현**: `refresh_tokens` 테이블 엔티티 및 리포지토리를 작성하여 토큰 원문 대신 SHA-256 해시를 저장하고 14일간 유효하도록 설정했습니다.
- **토큰 재발급 API (`POST /api/auth/refresh`)**:
  - 기존 리프레시 토큰을 검증하고 새로운 액세스 토큰 및 리프레시 토큰을 교체 발급(Rotation)합니다.
  - 동시에 들어오는 갱신 요청을 안전하게 처리하기 위해 DB 행 잠금(Pessimistic Lock)을 적용했습니다.
  - 만료되거나 존재하지 않는 토큰 요청 시 401 `INVALID_REFRESH_TOKEN` 에러를 반환합니다.
- **로그아웃 API (`POST /api/auth/logout`)**:
  - 해당 기기의 리프레시 토큰을 DB에서 삭제합니다. 이미 무효한 토큰 요청에 대해서도 204 응답을 반환합니다.
- **토큰 일괄 만료 및 정산 준비**: 비밀번호 변경/회원 탈퇴 등에서 사용할 `revokeAll(userId)` 로직과 새 토큰 발급 시 기존 만료 토큰을 정리하는 로직을 추가했습니다.
- **문서 및 테스트 코드 추가**: `docs/ERD.dbml`에 `refresh_tokens` 테이블을 추가하고, `RefreshTokenControllerTest`를 통해 기능 검증을 완료했습니다.

## 의도
액세스 토큰의 단기 유효기간으로 인한 사용자 불편을 줄이고, 보안성을 유지하면서 장기 로그인 상태를 지속할 수 있도록 하기 위함입니다. 토큰 원문 미저장(해시 저장) 및 토큰 회전(Rotation) 기법을 사용하여 리프레시 토큰 탈취 시 발생할 수 있는 보안 위험을 최소화하고자 했습니다.
