# 2026-08-28

## 요약
빌드나 린트는 통과하지만 실제 런타임 환경에서 동작하지 않던 각종 UI 버그와 세션 만료 처리를 대대적으로 수정했습니다. 이와 함께 개별 등록 API 연동, 중복확인, 도로명 주소 검색 등 핵심 비즈니스 로직을 백엔드 API와 맞추어 실제 동작이 가능하도록 구현했습니다.

## 변경 내용
- **환경 설정 개선**: Vite 설정에 `envDir`을 추가하여 루트 `.env` 파일을 멀티 앱이 로드할 수 있도록 수정하고 배포/로컬 개발 환경의 환경 변수(API 주소 및 주소검색 API 키) 흐름을 정상화했습니다.
- **세션 및 에러 처리**: 토큰이 만료되거나 401 응답을 반환할 때 세션을 자동으로 파기하고 로그인 화면(`/login?redirectTo=`)으로 안전하게 리다이렉트하는 `useSessionGuard` 훅을 적용했습니다. 또한, 에러 문구가 정의되지 않은 백엔드 에러는 서버 에러 메시지를 그대로 표출하도록 보완했습니다.
- **UI 및 레이아웃 버그 해결**: 민원인 전체 발급 시 용도 입력란 누락으로 신청 버튼이 상시 비활성화되던 이슈, 엑셀 파일 업로드 실패 후 재선택 무반응 오류, 헤더 영역의 사용자명과 남은 시간 컴포넌트 겹침 현상, `$variant` prop 전달로 인한 DOM 누수 경고 콘솔 에러를 해결했습니다.
- **API 연동**: 개별 등록 완료를 위한 자격증 생성 API(`POST /api/certificates/create`), 중복 대상자 확인 API(`POST /api/human/search`), 그리고 주소 검색 모달 컴포넌트를 실제 서비스 엔드포인트와 연동했습니다.
- **기타 변경**: 컴포넌트에 잔존하던 개발용 임시 더미 값("전재준" 등)을 소거하고, 사용자 목록 파싱 중에 비정상적인 데이터 행이 있어도 화면 전체가 깨지지 않도록 무시하는 안전 장치를 마련했습니다.

## 의도
런타임 환경에서 API 요청 주소가 비어 있어 발생하는 404 오류를 방지하고 백엔드 명세에 맞춘 정상적인 API 연동(경력 등록, 대상자 검색, 주소 연동 등)을 지원하기 위함입니다. 또한 서비스에 비정상적인 세션 만료나 단일 데이터 행 오류가 발생하더라도 프론트엔드가 안정적으로 이탈하거나 오류를 감내할 수 있도록 견고함을 다지고자 했습니다.

## 트러블 슈팅
- **로컬에서 API 요청 주소가 누락되어 404 에러가 발생하던 문제**
  - **문제**: 멀티 앱 모노레포 구조에서 하위 앱들이 루트 경로에 있는 공통 `.env` 설정을 읽어들이지 못해 `VITE_API_BASE_URL` 등이 비어 있었습니다.
  - **해결**: Vite 설정 내 `envDir`을 모노레포 루트 경로로 지시해 공유 환경 변수를 정상 병합하도록 수정했습니다.
- **통합 등록 업로드 실패 시 파일 재선택 불가 문제**
  - **문제**: 엑셀 업로드 과정이 실패했을 때 인풋 컴포넌트의 상태 처리가 리셋되지 않아 동일하거나 다른 파일을 다시 선택하는 동작이 무반응을 일으켰습니다.
  - **해결**: 에러 헨들링 시 인풋 엘리먼트 상태를 원복하고 엑셀 확장자를 `.xlsx`로 일관되게 고정했습니다.
- **민원인 발급 신청 버튼이 동작하지 않던 문제**
  - **문제**: 발급 신청 시 필수 필드인 '용도'를 입력받는 란이 화면상에 없어 폼 유효성 검사를 평생 통과할 수 없었습니다.
  - **해결**: UI 구성 단계에 용도 입력 필드를 추가 배치하여 버튼의 활성화 조건이 정상 작동하도록 구제했습니다.
