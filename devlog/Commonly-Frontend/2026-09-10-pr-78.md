## 요약
`develop` 브랜치에 누적되었던 기능 개선 및 버그 수정 사항들을 운영 환경인 `main` 브랜치에 반영하는 배포 PR입니다. 특히 빈 배열 응답 처리 오류로 인해 "업무 이력 조회" 화면에서 발생하던 문제를 해결하고, 초기 비밀번호 변경 화면 도입 및 권한 부족 시의 로그인 루프 수정 등을 통합 반영했습니다. 이와 함께 도로명주소 API 승인키 가이드 문서화 및 각종 테스트 검증을 완료했습니다.

## 변경 내용
- **API 응답 구조 개선 및 호환성 확보**: 빈 배열(`[]`) 응답에 대처하도록 `normalizePageEnvelope` 패턴을 적용하여 "발급 이력 응답이 올바르지 않습니다." 오류 해결 및 경력 직종/부서 필드 호환성 추가.
- **인증 및 세션 로직 보완**: 최초 로그인 시 비밀번호 변경을 제어하는 화면 및 가드 추가, 401 응답 발생 시 세션이 초기화되지 않아 무한 루프에 빠지던 버그 수정.
- **경력 등록 및 대상자 관리 연동**: 개별 경력 등록 및 대상자 생성, 주소지 전송, 기존 대상자 선택 기능을 유기적으로 연동하고 대상자 삭제 API 연결.
- **조회 필터 및 페이징 고도화**: 업무이력 조회 시 기간 및 성명 필터링 기능을 연동하고, 다음 페이지 유무를 판단하는 페이징 로직 적용.
- **기타 UI 복구 및 환경 구축**: 증명서 완료 화면에서 새로고침 시 정보가 유지되도록 복구하고, 루트 및 앱별 `.env` 병합 빌드 설정을 정리하였으며 도로명주소 승인키 발급 절차를 정리함.

## 의도
운영 브랜치의 코드가 과거 상태에 머물러 있어 최신 백엔드 명세와의 불일치(예: 이력이 없을 때 `[]` 빈 배열이 반환되어 정상 응답으로 파싱하지 못하는 문제)로 오동작하는 문제를 긴급히 해소하기 위함입니다. 아울러 그동안 `develop`에서 검증된 신규 기능들과 세션 제어 버그 픽스를 제품 환경에 일괄 릴리스하여 전반적인 서비스 품질을 맞추고자 했습니다.

## 트러블 슈팅
- **애플리케이션 전체 빌드(`tsc -b`) 실패 문제** → 루트 경로의 `vite.env.ts` 파일을 ESM 모듈로 올바르게 파싱하도록 설정하고 필요한 Vite 전역 타입을 연결하여 빌드 파이프라인 에러를 차단했습니다. (f121c4f)
- **컴포넌트 더미 값 제거 이후 기존 단위 테스트 깨짐 현상** → 테스트 환경에서 기본 스키마가 변함에 따라 깨졌던 `UserList` 및 `IndividualRegistrationComplete` 관련 테스트 명세 코드를 수정하여 전체 패스율을 100%로 회복시켰습니다. (c97cdb8)
- **401 Unauthorized 에러 시 비정상 세션 상태 유지로 인한 무한 리다이렉트 루프** → 단순 화면 전환 대신 세션 가드 로직을 개선하여 불필요하게 인증 만료 흐름이 정체되는 로직 버그를 끊었습니다. (371c9d3)
- **세션 연장 API 미지원 페이지에서 연장 버튼 노출 분기 버그** → 명세에 따라 버튼을 조건부로 숨기도록 하였으나, 화면 프로토타입 정합성 유지를 요청받아 기존 헤더 버튼을 상시 유지하도록 롤백(Revert) 처리했습니다. (7087a1f)
