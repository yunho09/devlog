# 2026-09-08

## 요약
민원인 회원가입 및 로그인 후 특정 페이지 진입 시 로그인 화면으로 무한 루프되던 버그를 해결했습니다. 백엔드에서 권한 부족 시 403이 아닌 401 응답을 내려주어 프론트엔드가 이를 세션 만료로 오인해 토큰을 지우던 문제를 수정했습니다. 이제 토큰이 여전히 유효하다면 401을 받아도 로그아웃시키지 않고 권한 부족 안내를 표시합니다.

## 변경 내용
- **인증 처리 로직 수정 (`api.ts`)**: 401 응답을 받아도 로컬에 저장된 토큰이 여전히 유효하다면 세션을 초기화하는 `UNAUTHORIZED_EVENT`를 발행하지 않도록 제한했습니다. 토큰이 없거나 실제 만료되었을 때만 로그아웃 처리를 수행합니다.
- **문구 변경 및 상수 내보내기 (`certificates.ts`, `index.ts`)**: 본인 경력 조회 및 발급 시 401 에러를 받으면 기존 "로그인이 만료되었습니다" 대신 전용 권한 안내 문구("본인 경력 조회 권한이 없습니다. 042-611-2114로 문의해 주세요.")가 출력되도록 변경했습니다.
- **회귀 테스트 3건 추가**: 
  - 유효한 토큰이 있을 때 401 응답 시 세션 유지 검증
  - 만료된 토큰 상태에서 401 응답 시 세션 정리 검증
  - 본인 조회 401 에러 문구 매칭 검증

## 의도
백엔드 API(`GET /api/certificates/self`)가 민원인 권한(`PETITIONER`) 제약으로 인해 권한 에러를 뱉을 때, 403 Forbidden 대신 401 Unauthorized를 반환하면서 프론트엔드 세션이 강제 종료되던 이상 동작을 방지하기 위함입니다. 백엔드 스펙에 임시 대응하되, 프론트엔드 자체의 토큰 유효성 검증을 덧붙여 실제 세션 만료와 권한 부족을 구분하고자 했습니다.

## 트러블 슈팅
- **문제** → 민원인이 로그인을 성공적으로 마친 뒤 `/career/issue` 진입 시 `GET /api/certificates/self` 호출에서 401 응답을 받음. 백엔드가 권한 부족에 대해 403이 아닌 401을 주기 때문에 프론트엔드가 이를 무조건 세션 만료로 인식하여 토큰을 삭제하고 `/login?redirectTo=...`로 리다이렉트시켜 무한 루프가 발생함.
- **해결** → 프론트엔드 API 인터셉터에서 401을 수신하더라도 클라이언트 측에 유효 기간이 남아있는 토큰이 있다면 세션을 정리하지 않도록 예외 처리함. 이후 화면에 강제 리다이렉트 대신 "본인 경력 조회 권한이 없습니다..."라는 구체적인 안내를 노출하도록 수정함.
