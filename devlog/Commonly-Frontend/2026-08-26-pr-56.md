# 2026-08-26

## 요약
어드민 웹 서비스의 사용자 목록 및 발급 이력(업무 이력) 조회 기능에 대한 API 연동을 완료한 PR입니다. API 클라이언트 구현과 단위 테스트 작성을 바탕으로, UI 컴포넌트에 페이징 및 상태 표시 기능을 추가했습니다. 또한, 검색어와 페이지 정보를 URL 파라미터와 동기화하고 잘못된 입력을 정규화하는 보정 로직을 적용하여 완성도를 높였습니다.

## 변경 내용
- 어드민 사용자 목록 및 발급 이력 조회 API 클라이언트 기능 추가 및 이를 검증하는 테스트 코드 작성
- `UserList` 및 `WorkHistory` UI 컴포넌트에 제어형 페이징 처리, 로딩, 에러, 빈 데이터 상태를 표시할 수 있도록 Props와 전용 CSS 스타일 보강
- `UserListPage`와 `WorkHistoryPage`에서 실 API 연동을 완료하고, 데이터 조회 중에는 검색 및 페이지 이동 조작을 제한하여 중복 요청을 방지하도록 개선
- 검색 키워드(keyword)와 페이지(page) 상태를 URL 쿼리 파라미터와 매핑하여 새로고침 시에도 기존 검색 상태가 유지되도록 동기화
- API 호출 전 URL 검색어의 공백을 제거(trim)하여 저장하고, 페이지 범위 보정 및 전달되는 page/size 인자값을 유한한 양의 정수로 정규화하는 안전장치 도입

## 트러블 슈팅
- **문제**: URL에 직접 검색 키워드(`keyword`)를 변경하여 진입했을 때, 화면 내의 검색 입력 필드 텍스트가 URL과 연동되지 않고 이전 상태에 머물러 있는 현상 발생
  - **해결**: URL 파라미터의 변경 사항을 감지하여 입력란의 상태값과 동기화해 주는 로직을 추가하여 브라우저 주소와 화면 간 일치성을 보장했습니다. (`1d976af`)
- **문제**: API 응답으로 넘어온 최대 페이지 한도보다 더 큰 임의의 페이지 번호가 URL에 기재되어 들어올 시 잘못된 조회 화면이 렌더링될 수 있는 취약성 존재
  - **해결**: API에서 넘어온 응답 범위를 기준으로 요청한 URL 페이지 번호가 범위를 넘어서면 올바른 범위 내의 유효값으로 자동 보정하는 예외 처리를 적용했습니다. (`e3b8eed`)
- **문제**: 목록 API 요청 시 유효하지 않거나 비정상적인 수치의 page/size 파라미터가 유입되어 서버 요청 실패가 우려됨
  - **해결**: 전달받은 파라미터를 정수로 변환 후 유한한 양의 정수 조건을 만족하도록 안전하게 정규화한 뒤 요청하도록 설계했습니다. (`b5b0f30`)
- **문제**: 사용자가 입력한 검색어의 공백이 API 처리 방식과 맞지 않아 클라이언트 측 URL 상태와 서버 측 쿼리 간에 불일치가 일어날 수 있음
  - **해결**: 검색 요청 직전과 URL에 상태를 저장하기 전에 텍스트의 앞뒤 공백을 제거(`trim`)하는 과정을 도입하여 데이터 일치성을 확보했습니다. (`c83f3c7`)
