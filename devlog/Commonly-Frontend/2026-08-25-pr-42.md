# 2026-08-25

## 요약
어드민(admin-web), 대민(civil-web), 유저(user-web) 서비스의 로그인 페이지에 로그인 API 연동을 완료하고, 세 개의 앱에서 공용으로 사용할 수 있는 통합 인증 유틸리티를 구축했습니다. `packages/utils` 패키지 내에 API 클라이언트, 로그인 비즈니스 로직 및 토큰 저장 모듈을 구성하여 중복을 최소화했습니다. 또한, 입력값 검증과 잘못된 토큰 응답에 대비한 방어적인 예외 처리를 추가하고 이에 대한 단위 테스트를 작성하여 안정성을 보장했습니다.

## 변경 내용
- **로그인 API 및 공통 인증 모듈 연동**: 어드민, 대민, 유저 웹 애플리케이션의 로그인 페이지(`LoginPage.tsx`)에 실제 API 연동을 적용했습니다.
- **인증 토큰(Access/Refresh Token) 관리 로직 구현**: 로그인 성공 시 액세스 토큰 및 리프레시 토큰을 안전하게 보관하고 관리하는 공통 모듈을 추가했습니다.
- **로그인 폼 입력 검증**: 아이디 및 비밀번호 입력 형식 검증 및 필드별 현지화된 오류 메시지 표시 로직을 구현했습니다.
- **공통 API 및 에러 처리 구현**: 공통 유틸리티 내에 네트워크 에러, 요청 취소, 토큰 처리 실패 등 다양한 예외 상황을 처리하는 공유 API 핸들러를 도입했습니다.
- **단위 테스트 구축**: 인증 및 로그인 로직의 동작을 검증하는 테스트 코드(`auth.test.ts`, `login.test.ts`)를 신설했습니다.
- **설정 및 환경 변수 추가**: 각 앱의 API 서버 설정을 위해 `.env.example` 파일을 정의하고, `.gitignore`에 AI 에이전트 상태 관련 파일을 추가했으며, 번역 리뷰 지원을 위한 CodeRabbit 한국어 설정 파일을 구성했습니다.

## 의도
이 변경은 다중 웹 애플리케이션 환경에서 핵심이 되는 사용자 인증 로직을 중앙 집중화하여 일관성을 높이고 중복 코드를 제거하기 위해 수행되었습니다. 모노레포 구조하에서 공통 모듈(`packages/utils`)에 로그인 비즈니스 로직과 보안 저장 유틸리티를 정의함으로써 향후 인증 정책이 변경되더라도 일괄적으로 유지보수할 수 있는 구조를 확립하고자 했습니다.
